# SFT 数据：366 条样本，按会话组切出 10 个验证组

## 结论

735 条带法回答，丢 369 条，留 366 条样本（训练 288 / 验证 78），覆盖 242 条处境、47 个会话组（51 个 session id）。丢的 369 条里 3 条是坏件（截断），366 条是同处境内的重复抽样：94 条归一化后逐字相同，244 条动作签名相同而措辞与命令不同，28 条没有动作、文字层决策四位相同且词集 Jaccard 在 0.51–0.88 之间（同一个决定换个说法）。

只按动作签名去重时留 291 条，那个键在回答没有 `tool:` 行时是空串，把同处境里「自行推进」与「问用户 A/B」并成了一条（GRW006 的 draw2 保留、draw4 丢掉）。现在空动作签名改用文字层决策签名：空签名组的 172 条候选先被四位分开，同一四位下再按词集 Jaccard ≥ 0.5 合并同一决定的改述。动作签名键下被并掉的 103 条无动作回答里，75 条是不同决策、各留一条，另 28 条是同一决定的改述、按 0.5 合并回去，所以无动作回答留 144 条，样本从 291 条回到 366 条——不是 394 条，103 条不都是不同决策。

394 → 366 的两个改法不是相加的，它们共同决定同一层：只把阈值从 0.9 降到 0.5（英文模式未加）时合并 33 条、样本 361 条；再加上 `eval/judge.py` 的 `STOP` 与 `CLAIM` 英文模式，四位重新分组后合并 28 条、样本 366 条。英文模式单独在 0.9 阈值下不改变任何合并（同四位配对里本来就没有一对到 0.9），它改变的是四位的取值与分组，所以两个改动合起来的净效果是 394 → 366。

366 条样本落到 175 条可训练规则上覆盖 77 条，剩下 98 条一条样本都没有。验证集是 10 个会话组（12 个 session id）、78 条，占样本 21.3%、占会话组 21.3%，同一会话组与同一处境都不跨两侧；fork 与它的父会话算同一个组，所以 01a03b52 与它的两个 fork 一起落在验证侧，没有一条训练样本与验证样本共享父会话上文。

全部数字由 `python3 scripts/build_sft.py` 重算并覆盖写盘，种子固定 20261020，连跑两次六个输出文件 sha256 不变。

## 去重前后

三种判据的对照，只有去重键不同，别的条件都相同：

| | 只判逐字重复 | 只按动作签名 | 现在（空签名改用文字层四位，同四位 Jaccard ≥ 0.5） |
| --- | --- | --- | --- |
| 候选 law 回答 | 735 | 735 | 735 |
| 坏件（截断） | 3 | 3 | 3 |
| 同处境重复 | 95 | 441 | 366（逐字 94 + 同签名 244 + 文字层 28 + 近重复 0） |
| 样本 | 637 | 291 | 366 |
| 每处境不同决策数 | 均值 2.63，最多 4 | 均值 1.20，最多 3 | 均值 1.51，最多 3 |
| 训练 / 验证 | 510 / 127 | 228 / 63 | 288 / 78 |
| 目标规则覆盖 | 77/175 | 77/175 | 77/175 |

为什么去重：同一处境的 prompt 逐字相同，抽样之间只差措辞与半条 shell 命令，它们的差别是同一件事的再次抽样。留着它们不给模型新信息，只给这条处境加权——一条被抽了 4 次的行为在 loss 里占 4 份。SFT 要的是「这种处境该怎么动」，处境的多样性来自 242 条处境本身，不来自同一处境的重复抽样，所以一处境一种决策只留一条。

为什么空动作签名不能并：735 条 law 回答里有 172 条没有 `tool:` 行，全是文字回复，空串把它们都归成同一个签名，同处境只留第一条，于是「先问用户选 A 还是 B」「先自己改掉」「先停住等确认」这几种不同决策只活下来一种。文字层四位签名就是给这 172 条一个能说出差别的键，代价是它只看得到提问、停住、断言、产物四件事。

## 每个处境不同决策数

366 条样本摊在 242 条处境上，均值 1.51 条，最多 3 条。

| 每处境不同决策数 | 处境数 | 样本数 |
| --- | --- | --- |
| 1 | 151 | 151 |
| 2 | 58 | 116 |
| 3 | 33 | 99 |
| **合计** | **242** | **366** |

这里的「不同决策」是去重键的取值个数：有动作时键是动作类型串（`read→files`、`bash→git` 等），没有动作时键是四位文字层签名。所以它既不是「不同行为数」的精确值，也不是下界——同一个签名下正文差别很大的抽样照样并成一条（244 条同签名丢弃里 37 条与代表的词集 Jaccard 低于 0.3），而四位签名把「问用户 A/B」和「问用户要不要继续」都记成 `1___`，同一四位下只有词集 Jaccard 低于 0.5 才分得开。它是「这批数据的去重键能分辨出的决策个数」，把它当「不同行为数」读是错的。

分布长这样：62%（151/242）的处境只有一种决策，24%（58）有两种，14%（33）有三种。33 条有三种决策的处境里 32 条靠文字层签名多出一种（同处境既有有动作的抽样，也有空动作但四位不同的文字回答），1 条（GRW011）本来就有三种动作签名。GRW006 是文字层的例子：三条无动作回答两两的四位不同或词集 Jaccard 低于 0.5（0011 对 0011 是 0.33，0011 对 1111 是 0.35），所以三条都留下——其中两条同是 0011，一条是 1111（先问用户选哪条、停住等确认）。

同一决定换个说法的三条现在会并成一条：GRW047 三条都是 1101，词集 Jaccard 0.59 / 0.61 / 0.88，全高于 0.5，只留 draw3 一条。复核点名的另两条没被并，原因不是阈值：GRW022 三条的两两四位并不相同（draw3 1101、draw4 1110、draw2 0001），四位不同就不进这一层；GRW057 的 draw3 与 draw4 同是 1110 但词集 Jaccard 只有 0.18，两条长回答用了几乎不同的词。以词集重合判「同一决定」的分辨率就到这里，写在下面限制第 6 条。

## 去重口径

去重只在同一处境内做，一条样本的生命周期是：坏件丢 → 按签名分组各留一条 → 近重复再挡一层。三种判据都取自 `eval/judge.py`，这里不另写解析器。

1. **动作签名**：`parse_actions` 解出回答里的每个 `tool: name(args)`，再用 `action_class` 判成类型（read / files / commit / dispatch / …），按出现顺序拼成一串。参数不参与，所以「同一条命令多半条」「grep 换成 rg」都算同一签名。签名非空时键是 `(处境, 动作签名)`，与只按动作去重时一致。
2. **文字层决策签名**：动作签名为空时，把回答压成四位——是否提问、是否停住等确认、是否下断言、是否有可核对产物。四个判定用 `eval/judge.py` 已有的函数：提问用切句后的 `QUESTION_END`，停住用 `STOP` 的标记词，断言与产物用 `count_checks` 判出的 `unlabeled_inferences` 与 `checkable_artifacts` 计数。位序固定为「提问/停住/断言/产物」，例如 `1111` 是提问且停住、有断言也有产物。同一处境内四位相同的为一组，组内 target 词集 Jaccard ≥ 0.5 才合并，否则各留一条——四位不同的一律都留。四位已经把「同一个决定」筛过一遍，组内只需证明两条在讲同一件事，所以这一层的阈值低于跨签名的 0.9：同一决定的英文改述、中文换词，词集重合就落在 0.5–0.9 之间。
   `STOP` 与 `CLAIM` 两个正则原本只有中文词，英文回答的「停住」与「断言」两位恒为 0，四位退化成「提问+产物」；现在两支正则各补了一组带词边界的英文模式（只增不删，中文那一支不变）。这个补充在 0.9 阈值下不改变任何合并（同四位配对里本来就没有一对到 0.9），在 0.5 下把合并数从 33 条降到 28 条，因为四位重新分组后贪心比较的配对变了。
3. **同组只留一条代表**：有动作的组留该处境出现次数最多的那套完整动作（工具名 + 压过空白的参数），平局取 `answers.jsonl` 里最早出现的那条，这样留下的是这条处境的主流行为。文字层组没有完整动作可比，代表取最早出现。
4. **近重复再挡一层**：签名不同（一个有空签名、一个没有，或动作类型串不同）但归一化 target 的词集 Jaccard ≥ 0.9 的，只留最早出现的那条。同签名的一对不再过这一层——它们已经被第 2、3 步判过，否则「四位相同但文本不同」的会被这一层按 0.9 阈值重新并掉，违背第 2 步。

四位那层的合并规则在这批数据上命中 28：172 条无动作回答里，同处境同四位的配对 58 对，32 对词集 Jaccard ≥ 0.5（无一到 0.9），按抽样顺序贪心比较后合并 28 条，合并的 Jaccard 落在 0.51–0.88。同一处理在自检里也会响：同四位、英文改述、Jaccard 0.68 的两条并成一条。

同签名丢弃的 244 条与代表样本的词集 Jaccard 中位数 0.53（p10 0.26，p90 0.89），其中 37 条与代表的词集重合低于 0.3，是同一处境下动作形状相同但正文差别较大的抽样。这是本次去重的取舍：同处境、同动作形状就算一种决策，正文差别照丢，因为 prompt 相同而 target 只差措辞的样本对 SFT 是同一个条件概率的重复观测。如果复核认为「同处境下正文差很多的回答应该各留一条」，那是把判据换成文本阈值（例如 Jaccard ≥ 0.7 才丢），样本量会比 366 再往上走。

## 坏件与丢弃

369 条丢弃记录全部在 `evidence/sft/dropped.jsonl`，每条带 `situation_id`、`session_id`、`draw`、`reason_class` 和一句 `evidence`（触发判据的原文片段、签名串、四位决策或 Jaccard 值），按 `(situation_id, draw)` 能回到 `answers.jsonl` 那一行。

| 类别 | 条数 | 判据 | 命中 |
| --- | --- | --- | --- |
| 空回答 | 0 | 去空白后为空 | 一条都没有 |
| 截断 | 3 | `finish_reason=length`，或末字不在句末字符集，或代码围栏为奇数，或引号外的括号/花括号未闭合 | GRW004 draw3（length，停在 966 字）；SIT120 draw2 与 draw4（`tool: write(...)` 的字符串没正常终止，`({` 未闭合） |
| 复读 | 0 | 同一行或同一段（≥20 字）出现 ≥3 次，或同一 10 词片段出现 ≥3 次 | 实测最大重复次数 2，两个判据都没到 3 |
| 回显 | 0 | 无工具动作，且回答的用词 ≥95% 已在处境里出现，且长度 ≤ 处境的一半 | 172 条无工具动作的回答里用词重合最高 0.891（SIT168 draw3，一条实测结论汇报），没过 0.95 |
| 重复 target | 94 | 同组内归一化后逐字相同，留代表那条 | 735 条里逐字重复的 94 条 |
| 重复动作签名 | 244 | 同处境内动作签名相同（参数不参与），留主流完整动作那条 | 441 条同处境重复里除逐字重复之外的 347 条中，244 条落在有动作签名的组里 |
| 重复文字层决策 | 28 | 同处境内动作签名都为空、四位相同，且词集 Jaccard ≥ 0.5 | 58 对同四位配对里 32 对过 0.5，贪心比较后合并 28 条（Jaccard 0.51–0.88） |
| 近重复 target | 0 | 同处境内签名不同但词集 Jaccard ≥ 0.9 | 这批数据里不存在这样的组合 |

文字层签名的净效果：172 条无动作回答原先按空签名只留 69 条（有空签名候选的处境各一条），现在留 144 条，**重新分开 75 条**。动作签名键下被并掉的 103 条里，75 条是不同决策（各留一条），另 28 条是同一决定的改述（按四位 + 0.5 合并回去）——所以 103 不是「决策不同的文字回答」的条数。

重复抽样是这批数据的主要损耗，不是坏件：温度 0.0 下同一条处境的 3–4 条抽样经常只差措辞与半条命令，这也是 `evidence/densify/summary.json` 里 `modal_label_stability` 只有 0.81 的同一个事实的两面。

判重只做在同一处境内。去重后跨处境逐字相同的 target 还有若干组，没有合并：合并会把某条 prompt 与它自己的 target 配错，而样本的价值在这对配对上。

## 切分

`situation` 到 `session` 是一对多，而且一个 session 可能有 fork，所以按**会话组**切：session id 取 `/forks/` 之前的那一段、再去掉末尾的 `.jsonl`，fork 与它的父会话落进同一个组。不这么归组就会泄漏：父会话一边、fork 一边，验证集里的样本与训练集里的样本共享同一段上文。之前的切分正是这种情形——校验侧有父会话 01a03b52，训练侧的 SIT102 与 SIT167 来自它的两个 fork。

现在 47 个会话组（51 个 session id）排序后用种子 20261020 打乱，顺次累加会话组进验证集，累计样本占比首次达到 0.175 就停。

| 侧 | 会话组 | session id | 样本 | 处境 |
| --- | --- | --- | --- | --- |
| 训练 | 37 | 39 | 288 | 191 |
| 验证 | 10 | 12 | 78 | 51 |

验证侧 10 个组（括号里是组里的 session id 数）：01a0eca7（1）、01a0bcc1（1）、01a11964（1）、01a09d9c（1）、01a09f6c（1）、01a0a1ef（1）、01a0f167（1）、01a089a3 的 raid_calc fork（1）、01a0eb30（1）、01a03b52（3：父会话 + 两个 fork）。与上一版切分相比，离开验证侧的是 helpagent 01a0adc7、pathlm 01a07b2b、resume_private 的 fork 01a08a32（这三条现在在训练侧）；进入验证侧的是 agentworld 01a0bcc1、murderMysteryGame 01a11964、mycar 01a09f6c、pathlm 01a0f167、resume_private 01a0eb30；mycar 01a09d9c、mycar 01a0a1ef、hf-research 01a0eca7、raid_calc fork、sys_gal 01a03b52 两侧都在验证侧，但 01a03b52 现在把它的两个 fork（SIT102、SIT167）一起带进了验证侧。

验证集占样本 21.3%、占会话组 21.3%、占 session id 23.5%。高于 0.175 是会话组粒度造成的：最后一个组一次把累计推过目标。程序里的断言检查的是切分规则本身的性质：加最后一个组之前累计 < 0.175，加完之后 ≥ 0.175，且超出目标的部分不超过一个组的占比。加上样本数相等、会话组与处境都不跨两侧，共四条。

写盘后独立核对过三条：两侧会话组交集 0；两侧处境交集也是 0（处境只属于一个 session）；两侧样本数相加等于全量。切分方式、种子、两组会话组与 session id 名单、fork→父会话的对照、每个处境的不同决策数分布、去重口径与文字层净效果、输入与输出文件的 sha256 都记在 `evidence/sft/split.json`。

## 运行时断言与自检

断言写在 `scripts/build_sft.py` 的 `assert_prompts` 里，构建时无条件执行，失败就退出、一个文件都不写，没有留开关。

- prompt 不含法条原文：拿 175 条可训练规则每条的「长度 ≥30 的首句」当法条独有短语（175 条），在 366 条 prompt 里逐条查，命中 0。
- prompt 不以任何 target 开头：275 个去重后的 target 前 40 字，366 条 prompt 没有一条以它们开头。
- 负控：把一条法条短语接进某条 prompt，断言触发并退出（`1 条 prompt 含法条原文，例：[('GRW001', 'laws.top_down', 'A rule is derived from this roo…']`）；把某条 target 的前 200 字前置到 prompt，断言同样触发（`1 条 prompt 以某条 target 开头`）。两个负控都跑过，所以这两条断言不是恒真的。

`--self-test` 跑 5 个坏件用例 + 7 个去重用例，全部命中预期：

- `same-signature`：同处境两条 read 形状、措辞不同 → 留 1 条，丢 `重复动作签名`。
- `near-duplicate`：同处境、签名不同（read vs other）但文本 92% 重合 → 留 1 条，丢 `近重复 target`。这条证明第二层判据会响，不是因为阈值永远不触发才不响。
- `different-behaviour`：同处境、一条 read 一条 edit → 两条都留，无丢弃。这条证明判据没有退化成「一处境只留一条」。
- `text-same-decision-near`：同处境两条都没有动作、四位相同、文本只差一个字 → 留 1 条，丢 `重复文字层决策`。这条证明空签名组的合并判据会响。
- `text-same-decision-far`：同处境两条都没有动作、四位相同但文本差得多 → 两条都留。
- `text-different-decision`：同处境两条都没有动作、文本逐字相同只差一个问号（`我先看一眼再决定？` vs `我先看一眼再决定。`）→ 四位不同，两条都留。这条是复核那类问题的负控：自行推进与问用户不能被并掉。
- `text-same-decision-english`：同处境两条英文回答、都没有动作、四位相同（都是 `1100`，靠新增的英文 `STOP` 把「停住」位判成 1）、词集 Jaccard 0.68 → 留 1 条，丢 `重复文字层决策`。这条就是复核点名的那类（同一决定的英文改述）：0.9 阈值下它不会被并，新阈值会。

## 限制

1. 366 条样本摊到 242 条处境，151 条处境只有一种决策。要在一处境里覆盖更多决策，得从 densify 之外的三个批次并进更多抽样，那是另一个决定。
2. 「每处境不同决策数」是去重键的取值个数，不是不同行为的精确计数：同动作签名而正文差别大的抽样仍会并成一条（37 条 Jaccard < 0.3 的被丢样本），四位签名也只分辨提问、停住、断言、产物四件事。读这个数时要带上判据的分辨率。
3. 覆盖 77/175 是下界：68 条处境没有标注，它们的覆盖记为 0；不重标是题面要求。
4. 复读、回显两类 0 命中是判据的结果，不是检测没跑：最大重复次数 2、无动作回答的最大用词重合 0.891 都记在上面。把阈值放松（例如行重复降到 2 次、重合降到 0.85）会开始丢正常的讨论型回答——172 条无工具动作的回答里大部分是有内容的回复，不是回显。
5. 文字层签名只对空动作回答生效；有动作的回答之间仍按动作类型串判，动作形状相同而正文完全不同的两条不会因为措辞不同而各自保留。这是判据的分辨率，不是遗漏。
6. 文字层签名依赖 `count_checks` 的启发式阈值（例如断言要有 `CLAIM` 无 `EVIDENCE` 无 `HEDGE` 的句子），它判错时两条不同决策可能被并、或两条相同决策被分。当前批次既合并了 28 条，也确有两类漏：GRW022 三条同一个决定因四位不同而全留，GRW057 的 draw3/draw4 四位相同但词集 Jaccard 只 0.18，中文与英文各一半的回答也容易被拆开。四位与词集重合都不是语义判据，没有独立标注可核对。
7. 代码块里的字符串内容不做结构检查。SIT087 draw3 与 SIT121 draw2 的 `newText` 里 JS 少一个 `}`，因为它在引号里，括号扫描看不见，这两条留在样本里。
8. 切分只按会话组分层，没有按工具种类或处境难度分层；验证集 10 个会话组 78 条，双侧 loss 的方差会不小，读曲线时要带这个前提。
9. `STOP` 与 `CLAIM` 的英文模式不是只服务这批数据：`eval/judge.py` 的 rubric 评测同样用它们，所以英文回答的 `unlabeled_inferences` 计数会变。在 `data/pairs-filtered.jsonl` 的 348 条回答上重算，`unlabeled_inferences` 有 65 个计数变化、`stops_before_gate` 有 1 个（全部是 0 变为非 0），`evidence/reports/rubric-diagnosis.md` 与 `evidence/reports/corrupted-pairs.md` 里的计数是旧正则下算的，重跑会变；重跑要重新调评委 API 花钱，本次没跑，那两份报告的数字因此未随本次改动重验。
