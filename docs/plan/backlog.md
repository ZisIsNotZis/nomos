# Backlog：DPO

类型：计划（备选）。所有者：主代理。上游：[设计](../method/design.md)、[计划](plan.md)。

DPO 现在不是主线，转为主线的 SFT 的后续可选阶段。留在这里的事实，是它为什么退到这一步。

## 两条负样本来源的实测结果

**用"同处境带法/不带法"当对。** 同一条件重采样的一致率只有 49.4% 与 58.0%，跨条件的差异是真的（不一致率 63.8% 对 50.6% 与 42.0%），但每条标签本身不稳：5 次抽样取多数后稳定度 0.808 与 0.843，两侧 5/5 一致的干净对只剩 8 条。

**用定向破坏当对。** 确定性模板造出 124 对，单因性 0.892。但盲审里 19 对中有 13 对可以只凭文风认出伪侧（68%），伤口是模板自己发明的占位符与不可执行命令。平滑到看不出痕迹的只有 6–7 对。

## 已经跑过的一次 DPO

73 对训练、按会话切验证。留出集奖励边际前后都约 0（−0.12 → +0.0064 的最佳配置），隐式准确率 0.444 → 0.500。诊断确认实现无误（prompt 掩码、标签顺序、手算 loss 全部对上），失效机制是未归一化的对数概率和让 β 在长度上被放大，以及样本量太小。

## 什么条件下值得再回来

- SFT 之后留出边际仍然分开得开，此时用 DPO 做收尾、只需要少量干净对。
- 出现能把伪侧做到盲测猜不中的构造方式（例如对真实回答做同长度、同文风的决策替换，而不是句级增删）。
- 处境池扩大，使稳定对的数量越过几百条。
