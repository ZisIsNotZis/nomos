# M1 计划

类型：计划。所有者：主代理。上游：[实验规格](../method/spec.md)、[预注册](../method/prereg.md)。

M1 不碰 GPU。全部工作是文本、API 与小脚本，因此硬件悬崖（2026-10-31）不影响 M1，只影响 M2 之后。

## 顺序

```
固定制度与节点索引
      ├── 分诊复核
      └── 冲突与优先级审计 ──┐
会话粗筛与差集裁决 ──────────┤
                            └── 处境格式与先导批
                                        ├── 效应量测量与基座门
                                        ├── 参照回答生成与配对
                                        └── rubric 与评委协议
                                                    └── 一条命令
```

## 工作包

### 固定制度与节点索引

把 `AGENTS.yaml` 的一个版本收进仓库做不可变固定件，生成节点索引。

- 产出：`constitution/AGENTS.yaml`、`constitution/lock.yaml`（上游路径、sha256、抓取时间）、`constitution/nodes.json`（点路径、节点原文、自身文本哈希、分类、是否可训练）。
- 验收：`nodes.json` 能从固定件重新生成且哈希一致；节点数与固定件对得上；引用的上游 sha256 与实测一致；行号只出现在生成的 markdown 表里，不参与任何连接。
- 边界：不与上游同步。上游变了是新版本目录加重跑，不是原地更新。
- 预算：无 API。

### 冲突与优先级审计

逐对检查 264 个叶子节点的动作是否相反、是否存在裁决路径（计数见 [constitution/nodes.json](../../constitution/nodes.json)）。

- 产出：`docs/method/conflicts.md`，三栏：真冲突（无裁决路径）、优先级处境（有裁决路径，需采样）、法定义的平衡点（是决策规则不是冲突）。
- 验收：每条真冲突给出两个节点、相反的动作、以及为什么现有优先级条款裁不了；一条都没有也是结论，要写下来。真冲突先报用户，相关处境不生成。
- 预算：无 API，主代理自己的判断，抽样由第二个模型复核。

### 分诊复核

复核起点文档的 208/33/16 分类（固定件重算为 222/11/31，判定程序见 [constitution/CLASSIFY.md](../../constitution/CLASSIFY.md)，计数见 [constitution/nodes.json](../../constitution/nodes.json)）与 29 条不训练清单。

- 产出：`docs/method/triage.md`，逐节点一行：分类、理由、是否可训练、检查形态（计数／二值／等级）。
- 验收：三类计数由脚本从固定件复算，与文档一致；每个节点都有分类；被排除的节点给出排除理由而不是沉默；改动原分诊的每一条都写一行理由。
- 预算：无 API 或极少。

### 会话粗筛与差集裁决

按 [规格 §2.5](../method/spec.md) 三步走。

- 产出：`mining/patterns/{coarse,fine}.yaml`、`mining/ledger.jsonl`（模式、命中数、抽样精度、来源）、`mining/windows/`（最小片段）。
- 验收：结构信号先跑，拿到不依赖措辞的基数；每条细集模式有抽样精度，样本量与抽样清单落盘；差集抽样裁决记录在账本里；原始日志不进仓库。
- 边界：只读会话文件，不改；不引用已弃用的索引文件；切片只作处境。
- 预算：grep 无成本；扩候选模式的 API 调用可忽略。

### 处境格式与先导批

定义处境的 schema 与第一批 40–100 条。

- 产出：`scenarios/schema.json`、`scenarios/pilot.jsonl`、`scenarios/coverage.json`。
- 验收：每条处境声明意图覆盖的规则 id；覆盖检查脚本能报出每条规则的计数与 m 的满足情况；schema 里 prompt 与 rubric 标签分离；sample 能以一处定义被训练与评测共同读入。
- 预算：以生成成本计，粗估占总预算的小头。

### 效应量测量与基座门

同一批处境上跑 DeepSeek 无法／带法两档，以及 base Qwen 的一档。

- 产出：`report/m1-effector.md`，三个数：带法与无法的维度差（效应量）、base 的可动作率、2B 自采失败里"流畅却违规"与"垃圾格式"的比例。
- 验收：每个数带区间与生成参数；三档用同一批处境、同一解码设置；过不了门就写"停止或改题"，不绕。
- 预算：本项目第一笔实质 API 支出；分档记账。

### 参照回答生成与配对

按 [规格 §2.3](../method/spec.md) 生成 chosen 与 rejected，并筛选。

- 产出：`data/pairs.jsonl`（prompt、chosen、rejected、筛选理由、触碰的规则 id）。
- 验收：prompt 里不含法条原文；rejected 只在 rubric 上有差异时入账；每对的差异定位到维度；抽样人工看过。
- 预算：按对计成本，先小批测单价再放大。

### rubric 与评委协议

- 产出：`eval/rubric.yaml`、`eval/judge.py`、一致率报告。
- 验收：每维有可数项；二值项占比报出；盲评在代码层保证（轨迹里没有模型标识）；同一批判 3 次的一致率实测并落盘；评委与生成者不同源。
- 预算：评委是最大单项支出，按 §3 记账，超预算减场景不减判读次数。

### 一条命令

- 产出：README 里的可运行命令，与 `make` 或等价入口。
- 验收：从干净 checkout 一条命令跑完覆盖检查与先导批的可判部分；README 里的命令被真的跑过一次，跑不通就不写进去。

## M1 完成的样子

`report/m1.md` 里每个数都能追到文件与行；四道门各有明确结论；预注册的 §2 样本量已填；README 的一条命令真的能跑。

## 预算

总量 1000 元，M1 只应花掉小头，因为 M1 的主体是审计与脚本。

- 生成（带法／无法／base 三档 × 先导批）：未知单价，先 10 条测一次。
- 评委：未知单价，判读次数已在预注册里定死，成本随场景数线性。
- 纪律：任何一批跑之前先算钱并写进计划；超支就减场景。

## 已知不确定

- 训练机是哪台、10-31 之后 4090 是否仍可用。这不影响 M1，但决定 M2 之后是否可行。
- 真实切片能捞到多少条可用处境。
- DeepSeek 无法与带法的真实差距。这是第一个要测的东西，也是本项目有没有信号的判据。
- 效应量门：探针 1（n=6）与探针 2（四项 rubric 饱和）都未决，探针 3（n=20）的配对强制选择未决；[探针 4](../../report/probe-4.md) 把样本扩到 183 条处境（51 个会话）后，全文与切片两个比较的强制选择都以排除 0.5 的区间偏好带法臂（0.594 与 0.590），门 1 从“未决”变成“通过”，H1 与 H2 都不成立。限制是有效独立单位只有 51 个会话、单次生成抽样与同家族评委，论文版本需要更多会话。
