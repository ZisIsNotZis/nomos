# 计划

类型：计划。所有者：主代理。上游：[设计](../method/design.md)。

当前路线是 SFT。DPO 作为备选留在 [backlog](backlog.md)，理由是实测：两轮构造负样本都没通过盲测，单次抽样重采样一致率只有 49–58%。

七步，按依赖顺序。每步给产出与验收，验收不过就停在那一步。

## 一 · 训练数据

**状态：数据基础已有。**

242 条合格处境，每条在带法条件下有 5 次抽样（共 735 条带法回答，落 `evidence/densify/answers.jsonl`）。

产出：`data/sft.jsonl`，每条记录 = 处境原文（prompt）+ 一条带法回答（target）。同一条处境的 5 条回答各算一条样本，重复文本去重；按会话切出验证集，同一会话不跨两侧。

验收：prompt 只含处境，绝不含法条原文（运行时断言）；每条 prompt 与 target 都完整；验证集按会话隔离。

## 二 · 数据质量

**状态：未做。下一个动作。**

1. 丢掉坏件：截断、复读、回显。
2. 丢掉同一条处境下重复的 target。
3. 标签：每条样本带上它来源的处境 id 与会话 id，便于按会话切分与逐处境归因。
4. 覆盖计数：242 条处境对 175 条可训练规则的覆盖，沿用 `data/coverage-counts.json` 的口径重算一遍，写清 SFT 实际触及多少条规则。

产出：`report/sft-data.md`。

验收：每条被丢样本有原因；覆盖数可重跑；坏件率如实报。

## 三 · 训练

**状态：未做。**

产出：`scripts/train_sft.py`，4-bit QLoRA，只对 target 部分算 loss（prompt token 掩掉，并在运行时断言掩码正确），按实测 p95 定序列长度，显存按 4090 上其他任务的实时占用定。

验收：至少 20 步、loss 有限、LoRA 参数确实收到非零梯度（断言，不靠警告）；训练集与验证集 loss 都落盘。

## 四 · loss / PPL

**状态：未做。**

产出：训练与验证 loss/PPL 曲线，逐 epoch。

验收：曲线在收敛区间；训练集与验证集差距报出来；证明的是"跑通了、学到东西了"，不是"学会了法"。

## 五 · 测量

**状态：未做。**

产出：三个水平在同一把尺子上的分数：

- 100 端：带法 DeepSeek 的回答（`evidence/densify/` 里 law 条件的多数答案）；
- 训练前：Qwen3.5-2B 在同一处境的回答；
- 训练后：同一处境的回答。

主尺子用**动作一致率**（确定性动作签名，与带法回答比，不需要评委），每处境多次抽样并报区间。rubric 作为辅助，照报不照判。

验收：三个水平同批处境、同采样协议、同解码参数；每处境的 `X = (qwen − base)/(100 − base)`；区间由抽样与处境的离散度合并得出。

## 六 · benchmark

**状态：未做。**

产出：开源套件（先测 headroom，30–70% 才用），训练前后各跑一次。

验收：每个数带区间；掉出噪声才叫掉。

## 七 · 发布

**状态：未做。**

产出：权重卡、数据卡、preprint 草稿、一条命令复现；`artifacts.tsv` 记大文件。

验收：README 那条命令自己跑过并写下实测时间；preprint 每个数字在 `report/` 找得到；不外传。

## 已知约束

- 显卡在 2026-10-31 之后是否可用未确认，且机器上另有项目占用约 16 GB。
- 处境池封死在 242 条、51 个会话，SFT 的样本量靠同一处境的多次抽样扩，不靠更多会话。
- 单模型（DeepSeek）的单次抽样本身不确定，所以训练前基线要多次抽样报区间。
