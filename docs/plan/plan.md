# 计划

类型：计划。所有者：主代理。上游：[设计](../method/design.md)。

七步，按你定的顺序。

## 一 · 生成处境

**状态：已有。** 455 个候选窗口 → 242 条合格处境（以用户轮结尾），来自 51 个会话；`evidence/` 里有抽取与分类脚本。

产出：一批处境，每条含工具面、若干轮对话、一个决策点。

验收：每条以用户轮结尾；每条声明想覆盖哪些规则。

## 二 · 生成正负样本

**状态：已有。** 183 条处境各生成两条回答：DeepSeek 带 `AGENTS.md`（chosen）与不带（rejected），落 `data/pairs.jsonl`。

产出：`data/pairs.jsonl`。

验收：同一处境两条回答都完整；prompt 里不含法条原文。

## 三 · 数据质量

**状态：未做。下一个动作。**

1. 丢掉两条完全相同的对。
2. 丢掉坏件：截断、复读、回显。
3. 标每对覆盖了哪些规则。
4. 跑覆盖计数：每条可训练规则被多少条处境覆盖；不足的改构造方式，不加样本。

产出：`report/data-quality.md`。

验收：计数脚本可重跑；每条被丢的对有原因；覆盖不足的规则列名字。
