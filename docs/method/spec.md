# 实验规格：把一个人写的操作法压进 2B 模型

类型：方法（规格）。所有者：主代理。上游：任务书。
起点是 `/home/z/vibe/resume_private/docs/method/policy-dataset.md`（只读引用，不在本仓维护）。那份分诊是这份规格的输入，不是它的上级。

## 0 主张

**相对主张**：在没有法条原文的上下文里，微调后的 Qwen3.5-2B 在"该动还是不该动"的判断上更接近"带法 DeepSeek"的水平，同时通用与 agentic 能力不跌出自身噪声带。

衡量只有一条：同一处境下按 rubric 逐维算出的归一化分 `X_d`。通用能力不是这条衡量的另一面，它是另一个问题，用开源套件单独回答。每个水平都带噪声底；噪声大到分不开，结论就是"分不开"，不是"没变化"。

**刻度**：`X = (qwen − base) / (deepseek − base)`，其中 base 是未微调的同尺寸模型，deepseek 是同一处境下带法的回答。两个刻度点都实测，不假定 base 为 0、不假定 deepseek 为 100。X 可以小于 0，也可以大于 100。

## 1 主体与参照

- 训练对象 Qwen3.5-2B（Apache 2.0，4-bit QLoRA）。0.8B 只作为可选的第二数据点，用于回答"这个尺寸以下还剩多少"；4B 不动，因为任务书写了 ≤2B，动它等于挪球门。
- 依据：Qwen3.5-0.8B 与 2B 于 2026-03-02 以 Apache 2.0 开源，4-bit 下均低于 2 GB；第三方 Intelligence Index 分别是 9 与 16（Artificial Analysis，2026-03-05）。9 这个量级很可能连"长法 + 多轮工具格式"都撑不住，会把题目降级成格式教学。
- 参照物是 DeepSeek 带法的回答，不是"法的正确读法"。理由：绝对主张需要整法裁判，而任何裁判都是某个模型对法的读法，争议无法消除；相对主张只需要一个可复现的参照物。
- 代价要写进结论：本研究的"与规则对齐"实际是"与 DeepSeek 对规则的读法对齐"。见 [limits](limits.md)。

## 2 数据契约

### 2.1 单位是处境，不是规则

一条样本是**一个真实或真实感的处境**：谁在什么状态说了什么、有哪些工具可用、此前发生过什么。规则是这条处境的标注，不是它的生成单位。

理由：模型在真实回合里失败的形态几乎总是"两条规则同时成立、指向相反动作"，按规则造样本会系统性地避开这种处境。

### 2.2 覆盖由声明加程序化计数保证

每条处境声明它**意图**覆盖哪些规则 id。覆盖检查只验证一件事：每条进入训练的规则至少出现在 m 条处境里，m 在预注册里定。分布允许自然不平衡，常见规则多、罕见规则少。

不检查"这条回答实际用到了哪条规则"。那需要整法裁判，代价高且争议大，而本研究不需要它。

### 2.3 三档回答与 DPO 对的构成

- prompt = 处境，**不含法条原文**。
- chosen = DeepSeek 带法对该处境的回答。
- rejected = DeepSeek 无法时对该处境的回答，**经过筛选**：只有当它与 chosen 在 rubric 上确实有差异时，这一对才入账。筛选不是伪造违规，是选掉没有教学信号的一对。
- 评测时上下文里同样**不放法**。放进去学的是读文档，不是内化。这一行是整个实验的成立条件，管线里最容易被顺手改成"把法喂进去更稳"。

两档回答的差距同时是一个结果量：DeepSeek 无法时的偏离率就是效应量，也是后面所有 X 的分母。它太小则本项目无信号，这一条在 §6 门里。

### 2.4 真实会话切片

本机 `~/.pi/agent/sessions` 有 3296 个 JSONL 会话、4.8 GB。它按项目目录分桶，第一层筛选用目录名，不用额外索引。

- 切片**只当处境，绝不当参考答案**：这些会话横跨多个版本的法，答案不可作为当前法的基准。
- 压成最小可复现片段（工具 schema + 2–4 轮 + 一个决策点），不把整段会话塞进训练。理由不是洁癖：长会话会训成"长上下文注意力"，而 2B 恰在长上下文上最弱。
- 原始日志不进仓库，脱敏后只留结构。

### 2.5 粗筛、细筛、差集

找"用户纠正 agent"的时刻分三步，差集本身是一次测量而不是遗漏：

1. **粗集 C**：高召回，按功能分类而不是按措辞，中英各取样，再让 DeepSeek 扩一批候选并入。
2. **细集 F**：抽样读 100 条算精度，只留验证过的模式。
3. **差集 D = C \ F**：抽样裁决，产出新模式与 C 的精度估计。

**结构信号优先于短语**，因为它跨语言且换说法绕不过去：用户在助手一次工具调用后立刻发话且没给新任务；连续多次工具调用之间无面向用户的检查点；用户在一两轮内近乎重复同一条指令（这就是"我不得不说第二遍"）；用户轮以否定词开头；用户引用助手原文再纠正；助手自己说"抱歉/我理解错了"且附近有工具调用。

用途决定精度要求：触发频率排序用粗集，宁可多；取真实违规时刻当骨架只从细集取，逐条看过。

### 2.6 冲突与优先级

三种情况必须分开，只有第一种是缺陷：

- **真冲突**：两条规则对同一动作给出相反要求，且没有优先级路径可走。这是法的缺陷，**报给用户，相关数据不生成**，等裁决。
- **表面拉扯、由优先级裁决**：`precedence.source_order`、`precedence.specificity`、`precedence.conflict`、`precedence.user_rank_scope` 的存在就是为了裁决它。这是正常处境，且必须被采样。
- **法本身定义了一个平衡点**：例如 `intent.objective.cost_function` 在时间与质量之间取舍。这是决策规则，不是冲突。

因此数据里会有一类"优先级处境"，它和"冲突"不是同一个词，不能混用。

## 3 评分

### 3.1 rubric 的结构

rubric 按规则维度组织：相位判断、授权/来源排序、证据义务、披露义务、提问必要性、越权动作、完成度。每一维由**可数项**和少量**等级项**组成。

- 可数项优先：越权动作次数、可推导却问了的问题数、被触发规则里守住的条数、门之前主动停住的次数。计数天然精确，不受措辞影响。
- 等级项只在该等级有行为定义时使用（例如"问了但只问必要的"与"问了可推导的"），中间档必须是可观察状态，否则不要中间档。
- 每个维度报 `X` 与区间；总分只作为便利汇总，并注明它的可靠性，不让总分冒充精度。

### 3.2 盲评与评委误差

- 评委不知道该轨迹来自哪个模型。
- rubric 的每一条来自 `AGENTS.yaml` 的规则表述；DeepSeek 的轨迹只用于校准刻度，不当标准文本。
- 评委与"带法生成者"不同源，否则它认自己的写法为合规。
- 同一批轨迹判 3 次或由两个不同家族各判 1 次，报一致率（二值项用 kappa）。评委分带误差，误差进入 `X` 的传播。
- 评委的散文输出用于发现未建模的失败类，不用来计分。

### 3.3 精度从哪里来

精度来自**独立项的数量**，不来自把 5 分拉成 50 分。单调变换不增加信息。

- 项数不等于有效项数：40 条 rubric 若都长在 6 个相关维度上，有效样本量接近 6。均值的标准误按 `n_eff` 算，按维度分开报。
- 分母太小时 `X` 病态（噪声除噪声）。判别方法是**逐项对比**：看 DeepSeek 通过而 base 失败的项有几个、集中在哪些维度。为 0 则该维度不可判别，报原始差距并声明，不硬求比值。

## 4 评测套件

| 目的 | 套件 | 依据 |
|---|---|---|
| 陌生法上的规则遵守（外部验证） | τ-bench 家族（retail / airline） | 公开、可本地跑、按数据库最终状态判成败、指标是 pass^k；其领域政策是另一部法，正好测迁移 |
| 多轮工具格式 | BFCL v4 的 multi_turn 子集 | 公开、本地免费、确定性判分 |
| 通用能力 | MMLU 子集、GSM8K、HumanEval 或 MBPP 迷你版 | 只回答"有没有掉" |

- 选套件的标准是**实测 headroom**：base 在该套件上落在 30–70% 的区间才有判别力，贴地板贴天花板都不行。先测，再冻结。
- τ-bench 的政策是放在上下文里的，所以它测"带着陌生法能不能守"，不是纯权重内化。这一局限写进结论，不藏。
- 通用套件的轨迹判不出规则（规则压根不被触发），它只回答"有没有掉"；域内的 agentic 能力由处境 rollout 回答，与规则遵守共用同一批轨迹。

## 5 试验与噪声

- **预注册的是停止规则和上限，不是确切的 n**：最少 3 次；某维区间半宽超过预注册的 δ 则加到 5 次；上限 5 次，主结果上限 8 次。看着数据决定何时停是 optional stopping，等于 p-hacking。
- **评测重复便宜**（同一 checkpoint，本地 GPU，分钟级），该多。
- **训练重复贵**（新 seed 会同时放大评委账单），只用于主表那一个数字，2–3 个训练 seed，报极差。
- loss / PPL 只作门禁：必须降；训练集 PPL 不能塌成死记。它不是结果。

## 6 门（跑数据之前必须过的四道）

1. **效应量门**：DeepSeek 无法时的偏离率相对误差足够大。若带法与无法几乎无差别，本项目无信号，停止或改题。
2. **基座能力门**：base 能否在处境格式里产出一个可判定的动作。不能则可判定动作的分母是 0，训出来的是格式不是政策。
3. **失败构成门**：2B 自身采样被拒的轨迹里，"流畅但在任务上却违规"占多少，"垃圾格式"占多少。垃圾占多数说明尺寸不到谈政策的阶段。
4. **冲突门**：冲突与优先级审计没有发现真冲突。发现了先报用户，不生成相关数据。

## 7 不训练的部分

工具与宿主绑定、模型无权执行的节点不进训练：`resources.work_areas.*`、`resources.machine.*`、`attention.communication.open_*`、`desktop_courtesy`、`resources.environment.bootstrap`、`cleanup_check`、`change.upkeep.rebuild_after_edit`、`proof.execution.check_gates`。它们由脚手架、CI 或外层权限执行，清单显式保留，不混进训练集把指标做高。

conceptual 与 definitional 节点不进样本主体，可作 chosen 的解释依据或系统提示。

## 8 已撤回的决定

保留死因，因为死因才是防止同类错误回来的东西。

- **「257 个节点、每格 k=2、N=5220」的轴格采样**：把规则当生成单位，系统避开规则交叉的处境，而那里正是失败发生的地方。改为处境优先采样。
- **把 257 当作节点总数**：257 是旧修订 `/home/z/vibe` 提交 1f47827 的叶子数，当前固定件的重算值是 264，节点数一律引 [constitution/nodes.json](../../constitution/nodes.json) 而不复述。
- **整法裁判（oracle）**：需要一个绝对"法要求什么"的判据，成本高且任何实现都是某一模型的读法。改为相对参照物。
- **「每规则一个确定性检查器定标签」**：单规则检查器只能判"这一面守没守"，判不了"这个动作对不对"。改为：标签来自轨迹在 rubric 上的剖面，单规则检查只用于定位失败。
- **把"授权"当场景级轴值**：授权不是场景的属性，是某个具体动作相对于某个具体来源的谓词。场景级布尔会把模型训成场景分类器。
- **用 `pi-web-session-index.json` 与 `missions/index` 当扫描入口**：前者是已弃用工具的产物，后者属编排层。撤回，改用会话目录名做第一层筛选。
- **把规则交叉叫"冲突"**：其中绝大多数是优先级裁决的常态，混用会让"发现了缺陷"这个信号失效。改称优先级处境，真冲突单列并上报。
