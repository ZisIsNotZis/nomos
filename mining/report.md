# 结构信号粗筛报告

类型：工作记录。所有者：主代理。上游：[实验规格](../docs/method/spec.md) §2.4 真实会话切片、§2.5 粗筛细筛差集。

这份报告只报结构信号的基数（base rate），不做内容判定，也不建纠正措辞词表（S6 与 S4 例外，见 §4）。产物：`candidates.jsonl`（每条一个窗口）、`sample-30.md`（30 条人读样本）、`check_redaction.py`（脱敏门）。

## 1 语料

语料根：`~/.pi/agent/sessions`。目录下共 3312 个 JSONL 文件、约 4.8 GB，按 cwd 目录分桶。文件分四种形态，本轮只扫描其中两种：

| 形态 | 文件数 | 是否扫描 | 理由 |
|---|---|---|---|
| 桶根会话 `--bucket--/<ts>_<id>.jsonl` | 167 | 是 | 真实交互会话，人在这儿说话 |
| 会话分叉 `--bucket--/<id>/forks/*.jsonl` | 108 | 是 | 同一会话的中途分叉，含主文件没有的尾部 |
| 子代理运行 `<id>/<run>/run-0/session.jsonl` | 2207 | 否 | 子代理运行，唯一一条 user 轮是派发提示，不会出现人的纠正 |
| 子代理转录 `subagent-artifacts/*_transcript.jsonl` | 830 | 否 | 同上，且记录 schema 不同 |

扫描 275 个文件、2449 MiB，覆盖 30 个项目桶。语料快照摘要 `3393332351685bdc`（对每个文件路径与字节数取 sha1）：计数绑定这个快照，语料仍在被写，摘要变了则两次运行的计数本来就不该相同。

分叉文件复制了主文件的历史，因此用户轮按（项目，消息 id）去重，共跳过 2149 条重复轮，分叉独有的尾部照常计入。

## 3 计数

分母是上面 1746 条人写的用户轮。一个窗口可以命中多个信号：`主信号` 每窗口只记一次，其和等于候选总数（455）；`任一信号` 允许重叠，故大于候选数。主信号按固定优先级取（S3 > S6 > S5 > S4 > S2 > S1，越靠前越具体），即 `candidates.jsonl` 里 `signals` 的第一项。

| 信号 | 扫描文件 | 命中（主信号） | 命中（任一信号） | 每 100 条用户轮 | 覆盖项目数 |
|---|---|---|---|---|---|
| S3 near-duplicate user turn (`S3_repeat_user_turn`) | 275 | 50 | 50 | 2.9 | 12 |
| S6 assistant self-flags a failure (`S6_assistant_self_flagged_failure`) | 275 | 100 | 100 | 5.7 | 12 |
| S5 user turn quotes the assistant (`S5_quotes_assistant_text`) | 275 | 51 | 51 | 2.9 | 12 |
| S4 user turn opens with a negation (`S4_negation_lead`) | 275 | 112 | 113 | 6.5 | 18 |
| S2 tool burst, no checkpoint (`S2_tool_burst_no_checkpoint`) | 275 | 16 | 22 | 1.3 | 11 |
| S1 interrupt after tool call (`S1_interrupt_after_tool_call`) | 275 | 126 | 187 | 10.7 | 20 |
| **合计** | 275 | **455** | — | — | — |

候选窗口 455 条；因疑似密钥丢弃 3 条（`dropped_for_risk`）。主信号合计与候选数一致：455 = 455。

**一个信号几乎对一切都成立。** 把 S1 读成「用户轮出现在任何用过工具的片段之后」，它就命中 1232 条用户轮、占 70.6%——在 agent 会话里「刚用过工具」几乎是常态，这个读法不能区分任何东西，只能当上界。所以本轮的 S1 取严格读法：用户发话前，助手在这条工具结果之后没有写过任何文本，占 10.7%。同一件事的两种读法差 7 倍，这是关于信号本身的发现，不是关于语料的。

## 4 信号定义与它实际测到什么

窗口按「说话轮」切：一条 user 消息是一轮，助手侧在它写出面向用户的文本处断成新的一轮，所以一轮是「一段被叙述过的工作」，而不是整段 user 到 user 的跨度。跨度另算，叫片段（segment），S2 与 S6 在片段上算。窗口取决策点所在片段起点起的最后 2–4 轮；一轮里的步骤只保留开头 1 步和结尾 6 步，中间标 `... N steps omitted ...`；被丢掉的轮标 `[... records X-Y omitted ...]`；整个窗口超过 4000 字符则中间截断、两端保留。

| 信号 | 结构判据（阈值在 `scan.py` 顶部） | 它比名义定义少测了什么 |
|---|---|---|
| S1 工具调用后立刻发话 | 前一轮助手工作以工具结果结尾，用户接着发话 | 「没给新任务」判不了；含正常汇报后的追问 |
| S2 连续工具调用无检查点 | 前一片段 ≥8 次工具调用，且片段内没有任何 ≥120 字符的助手段落 | 「长」不等于「人被迫介入」；8 与 120 都是取值，未校准 |
| S3 近乎重复同一条指令 | 与前 4 条用户轮之一的字符 4-gram Jaccard ≥0.60，正文 ≥12 字符 | 只认字面重复；换说法重复（「我是说…」）漏检，是下界 |
| S4 用户轮以否定词开头 | 首个 token 是否定词（中英各一小组，语法用词，不是纠正词表） | 「不错」与「不是呀」同族；否定开头不等于纠正 |
| S5 引用助手原文 | 用户轮里有 ≥30 字符片段逐字出现在前 3 轮助手文本里 | 引用被测到，「再纠正」没被验证 |
| S6 助手自陈失败 | 助手轮文本含道歉/认错措辞，且所在片段用过工具 | 唯一依赖措辞的信号；不道歉的失败全漏，是下界 |

## 5 判为不可靠或不可检出的部分

- **「没给新任务」（S1 的后半句）**：需要语义判断，结构信号做不到。S1 因此是上界。
- **换说法重复（S3 的漏检面）**：字符 4-gram 只覆盖同义复述的一部分；本轮不做 embedding，不估计漏检量。
- **失败但不道歉（S6 的漏检面）**：不做语义判定，无法估计；要等下一轮读样本。
- **助手是否真的错了**：六个信号都不判对错，只定位「可能是一个决策点」。本轮只产基数，这是刻意的。
- **工具 schema 原文**：会话日志里没有工具定义记录，只有工具调用名。窗口里的 `tool surface` 是本会话实际用过的工具名集合，不是模型当时看到的 schema；补齐需要宿主的工具注册表，不在本轮范围。
- **否定词的跨语言边界**：否定词表是手写的语法小表，只覆盖中英，法语、日语等全漏。

## 6 样本 30 条的选样方法

分层：按信号分组，每组最多 5 条；同组内每个项目最多 1 条，按（项目，会话文件，窗口 id）排序后取前几条；六组轮转拼满 30 条，不足则按信号顺序补，超出则截尾。所以样本不是前 30 条，也不依赖文件系统顺序。实际取到 30 条，每条正文截到 900 字符。

## 7 脱敏

窗口正文写入前替换：家目录与其它绝对路径、URL（带查询串的单独标注）、邮箱地址、各家 API key 前缀、GitHub 令牌前缀、云厂商访问键、聊天平台令牌、JWT、私钥块、`key: value` 形态的凭据、≥32 位十六进制串、≥44 字节 base64 串。含私钥块或高置信凭据形态的窗口不入库，直接丢弃并计入 `dropped_for_risk`——本轮真实丢掉了 3 条，里面确实有配置文件里抄出来的 API key 与 GitHub 令牌，不是理论风险。先脱敏再截断，免得截断把凭据切成两半、留下认不出的后一半。`check_redaction.py` 解码 JSONL 后逐字段扫描三个产物，命中即非零退出。原始会话不进仓库。
