# SFT 数据：291 条样本，按会话切出 8 个验证会话

## 结论

735 条带法回答，丢 444 条，留 291 条样本（训练 228 / 验证 63），覆盖 242 条处境、51 个会话。丢的 444 条里 3 条是坏件（截断），441 条是同处境内的重复抽样：94 条归一化后逐字相同，347 条动作签名相同而措辞与命令不同。上一版按「逐字相同」去重留 637 条，等于把 346 条同处境的重复抽样算成了独立样本，per-sample 数字（例如 `act_now` 一条规则一度报成 93 条样本）因此被放大；现在按动作签名去重，每处境平均 1.2 条样本。

291 条样本落到 175 条可训练规则上覆盖 77 条，剩下 98 条一条样本都没有。验证集是 8 个会话、63 条，占样本 21.6%、占会话 15.7%，同一会话与同一处境都不跨两侧。

全部数字由 `python3 scripts/build_sft.py` 重算并覆盖写盘，种子固定 20261020，连跑两次六个输出文件 sha256 不变。

## 去重前后

| | 去重前（只判逐字重复） | 去重后（判动作签名 + 近重复） |
| --- | --- | --- |
| 候选 law 回答 | 735 | 735 |
| 坏件（截断） | 3 | 3 |
| 同处境重复 | 95（逐字） | 441（逐字 94 + 同签名 347 + 近重复 0） |
| 样本 | 637 | 291 |
| 每处境样本数 | 均值 2.63，最多 4 | 均值 1.20，最多 3 |
| 训练 / 验证 | 510 / 127 | 228 / 63 |
| 目标规则覆盖 | 77/175 | 77/175（覆盖按处境计，去重不动它） |

为什么这样去重：同一处境的 prompt 逐字相同，抽样之间只差措辞与半条 shell 命令，它们的差别是同一件事的再次抽样。留着它们不给模型新信息，只给这条处境加权——一条被抽了 4 次的行为在 loss 里占 4 份。SFT 要的是「这种处境该怎么动」，处境的多样性来自 242 条处境本身，不来自同一处境的重复抽样，所以一处境一种行为只留一条。

## 每个处境贡献几条样本

291 条样本摊在 242 条处境上，均值 1.20 条，最多 3 条。

| 每处境样本数 | 处境数 | 样本数 |
| --- | --- | --- |
| 1 | 196 | 196 |
| 2 | 43 | 86 |
| 3 | 3 | 9 |
| **合计** | **242** | **291** |

分布长这样：81%（196/242）的处境只剩一条样本，18%（43）留两条不同行为，1%（3）留三条。一条处境的样本数就是它带的不同行为数——actions 签名不同才算两种行为，所以 2 条以上意味着同一处境下模型给出了两种动作形状（例如先只读、或直接改）。

这组数的含义要说清：去重后语料的主体是「242 条处境 × 各自一种主流行为」，第二、第三种行为只覆盖 46 条处境。如果训练后模型在「同一处境要不要直接动手」这类选择上表现单一，先看这里——不是模型偏好，而是数据每处境只有一条示范。

## 输入与口径

| 输入 | 用途 | 条数 |
| --- | --- | --- |
| `evidence/densify/answers.jsonl` 的 `arm=law` 行 | target | 735 |
| `evidence/slice-contrast/situations.jsonl` + `evidence/grow/situations.jsonl` 的 `excerpt` | prompt | 242 条处境 / 51 个会话 |
| `constitution/nodes.json` 的 `trainable` 节点 | 可训练规则表与断言短语 | 175 |
| `data/coverage.json` | 处境↔规则标注（沿用，不重标） | 174 条处境 |

一条 law 回答就是一条候选样本：prompt 是它那条处境的 `excerpt` 原文，target 是 `response` 原文，两者都不截断、不改写。归一化（去首尾空白、剥掉整体包住回答的一层代码围栏、压连续空白）只用于重复判定和断言，不写进样本。

本工作包只用 densify 批次，没去拼 `evidence/slice-contrast/`、`evidence/grow/`、`evidence/resample/` 三个批次里的其余抽样（映射见 `scripts/densify.py` 的 `SOURCES`）。

## 去重口径

去重只在同一处境内做，一条样本的生命周期是：坏件丢 → 同签名只留一条 → 近重复只留一条。

1. **动作签名**：`eval/judge.py` 的 `parse_actions` 解出回答里的每个 `tool: name(args)`，再用同一个文件里的 `action_class` 判成类型（read / files / commit / dispatch / …），按出现顺序拼成一串。参数不参与，所以「同一条命令多半条」「grep 换成 rg」都算同一签名。动作解析与分类不在这里另写一套。
2. **同签名只留一条**：同一处境内签名相同的样本归一组，每组留一条代表。代表取该处境出现次数最多的那套完整动作（工具名 + 压过空白的参数），平局取 `answers.jsonl` 里最早出现的那条——这样留下的是这条处境的主流行为，不是偶然少见的变体。
3. **近重复再挡一层**：签名不同但归一化 target 的词集 Jaccard ≥ 0.9 的，只留最早出现的那条。这一层在这批数据上命中 0：签名不同而文本仍≥0.9 相同的组合不存在。它留着是因为签名判据依赖解析（工具名写法、命令正文归类），文本判据不依赖，两者漏的东西不一样。两层都用自检用例证明会响（见「运行时断言」）。

去重后 347 条同签名丢弃记录，各自与代表样本的词集 Jaccard 中位数 0.51（p10 0.27，p90 0.85）；其中 47 条与代表的重合低于 0.3，是同一处境下动作形状相同但正文差别较大的抽样。这一条是本次去重的取舍：同处境、同动作形状就算一种行为，正文差别照丢，因为 prompt 相同而 target 只差措辞的样本对 SFT 是同一个条件概率的重复观测。如果复核认为「同处境下正文差很多的回答应该各留一条」，那是把判据换成文本阈值（例如 Jaccard ≥ 0.7 才丢），样本量会从 291 回到 400 上下。

## 坏件与丢弃

444 条丢弃记录全部在 `evidence/sft/dropped.jsonl`，每条带 `situation_id`、`session_id`、`draw`、`reason_class` 和一句 `evidence`（触发判据的原文片段、签名串或 Jaccard 值），按 `(situation_id, draw)` 能回到 `answers.jsonl` 那一行。

| 类别 | 条数 | 判据 | 命中 |
| --- | --- | --- | --- |
| 空回答 | 0 | 去空白后为空 | 一条都没有 |
| 截断 | 3 | `finish_reason=length`，或末字不在句末字符集，或代码围栏为奇数，或引号外的括号/花括号未闭合 | GRW004 draw3（length，停在 966 字）；SIT120 draw2 与 draw4（`tool: write(...)` 的字符串没正常终止，`({` 未闭合） |
| 复读 | 0 | 同一行或同一段（≥20 字）出现 ≥3 次，或同一 10 词片段出现 ≥3 次 | 实测最大重复次数 2，两个判据都没到 3 |
| 回显 | 0 | 无工具动作，且回答的用词 ≥95% 已在处境里出现，且长度 ≤ 处境的一半 | 172 条无工具动作的回答里用词重合最高 0.891（SIT168 draw3，一条实测结论汇报），没过 0.95 |
| 重复 target | 94 | 同处境内归一化后逐字相同，留代表那条 | 735 条里逐字重复的 94 条 |
| 重复动作签名 | 347 | 同处境内动作签名相同（参数不参与），留主流完整动作那条 | 441 条同处境重复里除逐字重复之外的 347 条 |
| 近重复 target | 0 | 同处境内签名不同但词集 Jaccard ≥ 0.9 | 这批数据里不存在这样的组合 |

重复抽样是这批数据的主要损耗，不是坏件：温度 0.0 下同一条处境的 3–4 条抽样经常只差措辞与半条命令，这也是 `evidence/densify/summary.json` 里 `modal_label_stability` 只有 0.81 的同一个事实的两面。

判重只做在同一处境内。去重后跨处境逐字相同的 target 还有 3 组，没有合并：合并会把某条 prompt 与它自己的 target 配错，而样本的价值在这对配对上。

## 切分

`situation` 到 `session` 是一对多，所以按会话切：51 个会话 id 排序后用种子 20261020 打乱，顺次累加会话进验证集，累计样本占比首次达到 0.175 就停。

| 侧 | 会话 | 样本 | 处境 |
| --- | --- | --- | --- |
| 训练 | 43 | 228 | 194 |
| 验证 | 8 | 63 | 48 |

验证集占样本 21.6%、占会话 15.7%。21.6% 高于 0.175 是会话粒度造成的：第 8 个会话带 17 条样本，把累计从 15.8% 一次推到 21.6%。旧版断言写死了 15–20% 区间，去重后样本变少、单会话占比变大，那个区间就成了「按会话切」做不到的要求，所以程序里的断言改成检查切分规则本身的性质：加最后一个会话之前累计 < 0.175，加完之后 ≥ 0.175，且超出目标的部分不超过一个会话的占比。计划对切分的要求只是「按会话切出验证集，同一会话不跨两侧」，没有比例区间，这两条断言加原有的两条（样本数相等、会话不交叉）覆盖了它。

写盘后独立核对过三条：两侧会话交集 0；两侧处境交集也是 0（处境只属于一个会话）；两侧样本数相加等于全量。切分方式、种子、两侧会话 id、每个处境的样本数分布、输入与输出文件的 sha256 都记在 `evidence/sft/split.json`。

## 覆盖

沿 `data/coverage.json` 的既有标注重算：一条规则被记为覆盖，意思是至少有一条幸存样本的处境被标注到它；没有标注的处境一律按不覆盖记，不重新标注。计数单位是**处境**，不是样本——所以按动作签名去重不改变覆盖数（242 条处境每条至少留一条样本）。

| 规则被多少条处境覆盖 | 规则数 |
| --- | --- |
| 0 | 98 |
| 1 | 26 |
| 2–4 | 26 |
| 5–9 | 11 |
| 10+ | 14 |
| **合计** | **175** |

覆盖 77 条，最多的处境数落在 `attention.phases.discussion.act_now`（93 条处境），其次 `attention.phases.discussion.round`（63）、`attention.phases.discussion.divergence`（56）。98 条一条都没有的包括 `laws.projection`、`laws.no_op`、`laws.top_down`、`intent.objective.product_bar.surface`、`intent.objective.mechanism_triad`、`intent.objective.true_metric`。逐条计数、未覆盖清单、以及 68 条没有标注的处境 id 都在 `data/sft-coverage-counts.json`。

这个 77 是下界而不是实测：242 条处境里 174 条有标注，68 条没有（`SIT` 与 `GRW` 批次之外的都不在标注覆盖范围内），它们带进来的覆盖被记成 0。

旧版报告把这些计数写成「多少条样本」，是错的：计的是处境数，637 条样本时也是 93 条处境。上一版 `act_now 93 条样本` 的说法按此更正。

## 运行时断言与自检

断言写在 `scripts/build_sft.py` 的 `assert_prompts` 里，构建时无条件执行，失败就退出、一个文件都不写，没有留开关。

- prompt 不含法条原文：拿 175 条可训练规则每条的「长度 ≥30 的首句」当法条独有短语（175 条），在 291 条 prompt 里逐条查，命中 0。
- prompt 不以任何 target 开头：231 个去重后的 target 前 40 字，291 条 prompt 没有一条以它们开头。
- 负控：把一条法条短语接进某条 prompt，断言触发并退出（`1 条 prompt 含法条原文，例：[('GRW001', 'laws.top_down', 'A rule is derived from this roo…']`）；把某条 target 的前 200 字前置到 prompt，断言同样触发（`1 条 prompt 以某条 target 开头`）。两个负控都跑过，所以这两条断言不是恒真的。

`--self-test` 跑 5 个坏件用例 + 3 个去重用例，全部命中预期：

- `same-signature`：同处境两条 read 形状、措辞不同 → 留 1 条，丢 `重复动作签名`。
- `near-duplicate`：同处境、签名不同（read vs other）但文本 92% 重合 → 留 1 条，丢 `近重复 target`。这条证明第二层判据会响，不是因为阈值永远不触发才不响。
- `different-behaviour`：同处境、一条 read 一条 edit → 两条都留，无丢弃。这条证明判据没有退化成「一处境只留一条」。

## 限制

1. 291 条样本摊到 242 条处境，196 条处境只有 1 条样本。要在一处境里覆盖第二种行为，得从 densify 之外的三个批次并进更多抽样，那是另一个决定。
2. 去重把同处境、同动作形状的样本压成一条，47 条被丢样本与代表的重合不到 0.3：正文差别较大的回答也一起丢了。这是判据的直接后果，取舍写在「去重口径」里。
3. 覆盖 77/175 是下界：68 条处境没有标注，它们的覆盖记为 0；不重标是题面要求。
4. 复读、回显两类 0 命中是判据的结果，不是检测没跑：最大重复次数 2、无动作回答的最大用词重合 0.891 都记在上面。把阈值放松（例如行重复降到 2 次、重合降到 0.85）会开始丢正常的讨论型回答——172 条无工具动作的回答里大部分是有内容的回复，不是回显。
5. 动作签名只看 `tool: name(args)` 的形状。不带这一行写法的回答签名都是空串，735 条 law 回答里有 172 条，同一处境里它们被并成一条：103 条当 `重复动作签名` 丢掉，69 条留作各自处境的无动作代表。
6. 代码块里的字符串内容不做结构检查。SIT087 draw3 与 SIT121 draw2 的 `newText` 里 JS 少一个 `}`，因为它在引号里，括号扫描看不见，这两条留在样本里。
7. 切分只按会话分层，没有按工具种类或处境难度分层；验证集 8 个会话 63 条，双侧 loss 的方差会不小，读曲线时要带这个前提。
