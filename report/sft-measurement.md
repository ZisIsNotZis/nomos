# 窄版适配器的动作一致率测量

状态：**终版**（`evidence/measure/summary.json` 的 `status: final`）。快照 `answers.jsonl` 1452 行 = 242 条处境 × 3 条抽样 × 2 侧（sha256 前 16 位 `52da1478f19e780a`），两侧都齐全的处境 242/242，生成已完成，没有半条处境。匹配锚点在 `evidence/measure/anchor-matched/`（`summary.json`、`answers.jsonl` 888 行、`pilot.json`），888 次 DeepSeek 调用花费 ¥0.7115，解码参数与 base/post 相同且 prompt 逐条 sha256 核对同字节。

口径一与格式/决策分解在 **n_pairs = 148 / 242（覆盖率 0.612）** 的处境上算，口径二在 169 条上算，口径三在各自子集上算，本页每个数字都带自己的 n。`n_pairs` 是「动作参照物可用且两侧各 3 条抽样齐全」的处境数；覆盖率不到 1 的原因不是生成缺失，而是 242 条处境里有 94 条的动作参照物定不下来（54 条空参照物、40 条没有多数，见「与哪一侧比」），这些处境的一致率不进任何分子分母。

主指标（动作签名一致率）在基座侧贴到 0，但那个 0 里混了两件事：写不出可解析工具行，与写了之后动作选得不对。所以 `--analyse` 并列报三个口径与一个分解，结论必须三个一起给，口径见下节。

## 口径

### 处境与 prompt

242 条处境 = `evidence/slice-contrast/situations.jsonl` 的 183 条 + `evidence/grow/situations.jsonl` 的 59 条，id 固定。每条处的 prompt 是处境原文 `excerpt` 接上 slice-contrast 的续写指令，**不含任何法条原文**：生成前用 `build_sft.law_phrases()` 的 175 条短语逐条查过，命中即停。

### 两套解码，哪些比较同协议

这份测量里有两套解码，混用它们就是换了一把尺子，所以先写清每套是什么，再写哪些比较能相减：

| 批次 | 模型 | temperature | top_p | max tokens | 抽样 | 法条位置 | 证据 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| base、post | Qwen3.5-2B（基座 / 窄版适配器） | 0.7 | 0.95 | 320 | 每处境每侧 3 | 无 system 消息 | `evidence/measure/answers.jsonl` |
| 匹配锚点 | deepseek-flash，thinking 关闭 | 0.7 | 0.95 | 320 | 每处境每侧 3 | 只在带法条件进 system 消息 | `evidence/measure/anchor-matched/answers.jsonl` |
| 参照物与旧刻度 | deepseek-flash，thinking 关闭 | 0.0 | 默认 | 600 | 3.04（242 条里 233 条 3 条、9 条 4 条） | 只在带法条件进 system 消息 | `evidence/densify/answers.jsonl` |

**同协议、可以相减的比较**：base 对 post（同一条 prompt、同一套解码、同一批抽样数）；匹配锚点内部的带法对不带法（同一条 prompt、同一套解码）；旧批次内部带法对不带法（同前）。

**跨协议、不能当同一把尺子的比较**：旧的 bare 0.3502 对 base/post（0.0 对 0.7、600 对 320、3.04 对 3 条）；参照物那条 1.000 对 base/post（它是 0.0、600 下的多数签名，base/post 在 0.7、320 下被它评分）。旧的 bare 刻度换成同协议读数后是 0.2815（见下表），两者差 0.0687 [0.0146, 0.1239]，这一份差异只来自解码，不是能力。

解码参数生效的证据（`evidence/measure/anchor-matched/pilot.json`，20 条处境 × 2 条件 × 3 条 = 120 次调用）：每次调用都返回了 `usage` 与 `finish_reason`；`completion_tokens` 最大 291（全量 888 条里最大 320，11 条触顶，`finish_reason: length`）；prompt 与 base/post 逐条 sha256 同字节 120/120；不带法条件的 `system_chars` 全为 0。API 不回显 temperature 与 top_p，所以这两项只有「发送成功、请求体里有、无报错」的证据，没有返回值的证据；`max_tokens` 有可观测上界（`completion_tokens ≤ 320`）。

### 动作签名怎么取

以下是口径一（主指标）的完整口径，另外两个口径与它们共用的参照物规则、以及主指标的格式/决策分解，在后面的「三个口径与一个分解」一节。

每条回答经 `eval/judge.py` 的 `parse_actions` 抽出所有 `tool: name(args)`，再由 `resample_actions.signatures` 压成签名元组：`bash` 记 `bash` 加规范化后的命令，读写类工具记工具名加目标路径，其余只记工具名。签名是**有序元组，全等才算命中**——回答里多一个动作、少一个动作、动作顺序不同都算不一致。回答里一个可解析动作都没有时签名是空元组，它不是一条动作，也不是缺失值。

### 与哪一侧比

比的是**带法 DeepSeek 的多数签名**（`evidence/densify/answers.jsonl` 的 `law` 条件，每处境 3–4 条抽样），即「读了法之后的动作」。选它作参照物是因为它自己和自己最一致，不是因为它是对的。

参照物那条 1.000 是**定义**，不是测量：参照物就是「每条处境唯一那一个多数签名」，所以带法侧对它自己必然是 1.0。同协议下真正可测的带法侧自洽度是「再抽一条带法回答、还是同一个签名」的比例，旧批次（0.0、600）是 0.8407，匹配解码（0.7、320）对同一个固定参照物只有 0.3311 [0.2725, 0.3919]。所以量适配器离「带法 DeepSeek」有多远时，1.000 那端是虚高的天花板；同解码可比的那端是 0.3311。

不带法 DeepSeek 给参照物标刻度，而且有两套：旧批次（`evidence/densify` 的 `bare`，0.0、600）与匹配锚点（0.7、320、3 条，只覆盖参照物可用的 148 条处境）。同协议的刻度是匹配锚点那一套，旧的那一套作跨协议对照保留。

参照物只在两个条件同时成立时才算**可用**：

- **定下来了**：law 条件里出现次数最多的签名至少拿到 2 票。3 条抽样两两不同时票数是 1，那不是一个多数，只是第一个出现的签名，把它当参照物等于把噪声当答案。
- **非空**：多数签名本身含至少一个动作。空签名当参照物时「基座也什么都没说」会被记成命中，这是把「两侧都没动作」当成「学会了动作」。

两者之一不成立的处境**不计入一致率**，并分别计数报出（`reference_selection`）。

### 一致率的分母

每处境每侧的一致率 = 该侧 3 条抽样里签名等于参照物的条数 / 3；某个侧只有 1–2 条抽样时**不给一致率**（半条处境的 0/1 会被当成真实比例），该处境在这一侧记为缺失并单独计数（`situations_base_partial`）。跨处境的一致率 `base_mean`、`post_mean` 是可用处境上的一侧一致率的算术平均，分母是可用处境数。

### X 的定义

X 是「适配器补上了多少法条带来的剩余空间」：

    X = (post_mean - base_mean) / (1 - base_mean)

`base_mean` 与 `post_mean` 取**两侧都齐全的同一批可用处境**（配对）。先算两侧均值再算比率，不是先按处境各算一条 X 再平均：单处境 X 在 `base = 1` 时无定义，逐条平均就必须把那些处境整条丢掉，均值因此有偏；而 3 条抽样下单处境一致率只能取 0、1/3、2/3、1，比率抖动极大。逐处境的 `X_situation` 只作诊断列输出在 `evidence/measure/per-situation.jsonl`，不进 X。

### 区间怎么算

配对自举，**重抽单位是处境**，不是抽样条数：每次从配对处境里有放回抽 n 条处境，同一批处境的两侧一致率一起进来（base 与 post 的相关性保住），重算 `base_mean`、`post_mean`，再算该次重抽的 X。2000 次重抽取 2.5% / 97.5% 分位作区间。某个重抽样本里 `base_mean` 恰好等于 1 时，该次的 X 无定义，跳过并计入 `X_replicates_undefined`；全部重抽都无定义时区间是 null。

### base 接近 1 或 0 时

- **`1 - base_mean = 0`（base 已经满分）**：X 无定义，报 `X_status: undefined_no_headroom`，也不给区间——剩余空间是 0，比率没有意义。绝不返回一个补丁值。
- **`1 - base_mean` 很小**：X 照算，但同时报 `X_near_ceiling: true`（阈值 0.2）与 `X_headroom`。空间小则同样的差值被放大，区间会很宽，读的时候必须带区间而不是只看点估计。
- **`base_mean = 0`**：X 有定义，等于 `post_mean`（分母是 1）。此时 X 与原始一致率同义，「补上剩余空间的比例」这个含义消失，报告里要说明是这一种情况。
- 生成尚未完成时（`post_mean` 缺失）X 一律是 null，`X_status: undefined_adapter_side_missing`，不当 0 处理。

### 可数对照

另外报一个不经评委、不看参照物的量：回答里有没有至少一个可解析动作（签名非空）。它只说明模型「说不说话」，不说明说得对不对，用来把「一致率高」与「动不动手」分开。

### 三个口径与一个分解

口径一是主指标：**动作签名一致率**，回答压成 `tool: name(args)` 的有序签名，与带法 DeepSeek 的多数签名全等才算命中。它的前提是回答里先出现可解析的工具行，而训练前基座这个前提基本不成立（只有约 6% 的回答有可解析动作），所以 base 侧贴到 0，0 里分不清「不会写工具行」与「写了也不对」。两个并列口径与一个分解就是为了把这层拆开：

| 口径 | 量什么 | 参照物 | 命中前提 |
| --- | --- | --- | --- |
| 一、动作签名一致率（主指标） | 3 条抽样里动作签名等于带法多数签名的比例 | 带法 DeepSeek 的多数**动作**签名 | 回答里要有可解析的 `tool: name(args)` |
| 二、文字层决策签名一致率 | 3 条抽样里**文字签名**等于带法多数文字签名的比例 | 带法 DeepSeek 的多数**文字**签名 | 无，只看文字 |
| 三、动作可比子集一致率 | 只在该侧已有可解析动作的处境上算口径一 | 同口径一 | 同口径一，但只比可比的地方 |

分解把口径一的变化拆成两项：(a) 回答里出现可解析动作的比例变化，(b) 在有动作的回答里签名吻合的比例变化。

### 口径二：文字层决策签名一致率

每条回答压成一个定序元组，元素是「这条回答在文字层做了哪几种决策动作」，全等才算同一签名（与动作签名一样严，多一种或少一种都不算）：

| 特征 | 含义 | 判据（全部取自 `eval/judge.py`，本脚本只组合，不另写一套） |
| --- | --- | --- |
| `asks` | 提了问 | `QUESTION_END`：以问号或「吗 / 呢」收尾的句子 |
| `stops` | 停住等确认 | `STOP`：等确认、请你决定、先不动手一类门前停顿标记 |
| `asserts` | 下了断言 | `CLAIM` 命中且同一句 `EVIDENCE` 与 `HEDGE` 都不命中，与 `count_checks` 的「未标注推断」同一条过滤 |
| `artifacts` | 给了可核对产物 | `ARTIFACT_PATH / HASH / LINE / NUMBER / QUOTE`：路径、哈希、行号、带单位数字、反引号原文 |

参照物与口径一同一条规则：带法 DeepSeek `law` 条件的多数文字签名，票数 ≥ 2 且签名非空才可用（`text_signature.reference_selection`）。四种特征一个都没命中时签名是空元组，它不是缺失值，但空签名当不了参照物——那会把「两侧都没说什么」记成命中。

这个口径的力量与弱点都在同一个地方：它不需要模型写出工具行，所以基座侧不再贴地板；但单特征签名（只命中一种）区分力很弱。`text_signature.reference_shape` 报出参照物里单一特征签名的占比（快照里 0.645，其中 0.49 是只剩 `artifacts`），读口径二时必须带着这个数：那 0.49 的处境上，「一致」只意味着两侧都只给了可核对产物。

### 口径三：动作可比子集一致率

一个处境进入该侧子集的条件是：该侧 3 条抽样里**至少 1 条**动作签名非空。子集回答的是「已经在写工具行的那些回答里，动作选得对不对」，把「写不出工具行」排除在外；`paired` 子集要求两侧都至少 1 条有动作，只有配对子集上的两侧一致率才能相减。

子集处境数少于 `MIN_CONCLUSIVE_SITUATIONS = 30` 时标 `conclusive: false`，只作参考：这么小的 n 上比例的区间宽到分不清「格式」与「决策」，写进结论就是把小样本当结论。

### 主指标的格式/决策分解

参照物非空时，没有可解析动作的回答永远命中不了，所以每个处境的

    mean 一致率 = P × A

P 是回答里有可解析动作的比例，A 是这些回答里签名吻合的比例。Δ 可以精确拆开，但拆法不止一种，份额随约定变：

中点约定（Kitagawa，`format_part` / `decision_part`，Ā 与 P̄ 取两侧中点）：

    Δ = (P_post − P_base)·Ā + (A_post − A_base)·P̄

以 base 为起点的两项加交互项（`*_at_base` / `interaction_part`）：

    Δ = ΔP·A_base + ΔA·P_base + ΔP·ΔA

- 第一项是**格式项**：模型开始写工具行带来的那一份。
- 第二项是**决策项**：写了之后选的动作对不对带来的那一份。
- 第三项是**交互项** ΔP·ΔA：起始写不出工具行、吻合率也几乎为零时，两件事同时变才会产生的那一份。
- 两种拆法都精确等于 Δ（中点那套的 `residual`、base 那套的 `at_base_residual` 只应是浮点误差，`--check` 两种都断言）。第一套把交互项平分成两半，第二套把它单列，所以「格式占几分」这个问题没有与约定无关的答案。
- `format_share` = 格式项 / Δ（中点约定）：1 表示提升全来自格式，0 表示全来自决策，`Δ = 0` 时无定义（记 null，不补 0）；`interaction_share` = 交互项 / Δ。
- 分解在主指标同一批处境上算（两侧齐全时用配对集，否则用参照物可用的 base 处境），所以 P、A 与 `base_mean` 对得上；某一侧没有一条动作时 A 无定义，分解标 `undefined_no_emitting_answer_on_a_side`，不拿 0 冒充。

分解的区间用按处境配对自举（`bootstrap_decomposition`），给 Δ、中点两项、base 三项各自一条区间。

## 结果（终版，n_pairs = 148 / 242，覆盖率 0.612）

三个本地水平（base、post 与匹配锚点）共用同一批处境、同一个 prompt、同一套解码，每处境每侧 3 条抽样；参照物与旧不带法刻度来自另一套解码（见「两套解码」）。下表每个点估计都是 n_pairs = 148 条处境的算术平均，方括号是按处境配对自举的 95% 区间（2000 次重抽，2.5% / 97.5% 分位）。

### 口径一：动作签名一致率（主指标，n_pairs = 148）

| 水平 | 解码 | 一致率 | 区间 |
| --- | --- | --- | --- |
| base（训练前基座） | 0.7 / 0.95 / 320 | 0.0023 | [0.0000, 0.0068] |
| post（窄版适配器） | 0.7 / 0.95 / 320 | 0.0968 | [0.0586, 0.1374] |
| 不带法 DeepSeek（旧刻度，跨协议对照） | 0.0 / — / 600 | 0.3502 | [0.2815, 0.4234] |
| 不带法 DeepSeek（匹配锚点，同协议） | 0.7 / 0.95 / 320 | 0.2815 | [0.2207, 0.3401] |
| 带法 DeepSeek（匹配锚点，同协议） | 0.7 / 0.95 / 320 | 0.3311 | [0.2725, 0.3919] |
| 带法 DeepSeek（参照物本身） | 0.0 / — / 600 | 1.000 | 定义上，不是测量 |

base 侧是 444 条回答里 1 条命中，区间下界贴 0 是「绝大多数处境 3 条抽样全部不命中」的离散结果，不是真值 0。

同协议的刻度是 0.2815：一个没读法的强模型在 27–34% 的处境上说中带法动作，适配器是 9.7%，两者都在同一套解码下，这个差（≈0.185）才是能力差。旧刻度 0.3502 把不带法侧抬高了 0.0687 [0.0146, 0.1239]，那一份是解码差不是能力差；旧读数里的 bare 抽样在 0.0 下生成，却拿去与 0.7 下的 base/post 比。

匹配锚点里还有一个更要紧的数：同一套解码下，**带法侧对同一参照物只有 0.3311，不带法侧 0.2815，差 0.0496 [−0.0068, 0.1059]**。也就是说，在这个 148 条处境、这个口径、这套解码下，「读了法」与「没读法」的差异小到区间跨 0——这个尺子在 0.28–0.33 这个位置上分辨不出法的作用。适配器的 0.0968 低于两者，这个「低」是可信的（差距远大于区间宽），但把它读成「补上了多少法条效果」没有意义：尺子连法本身都量不出来。

### 口径二：文字层决策签名一致率（n_pairs = 169）

口径二的参照物可用处境是 169 条（47 条空参照物、26 条没有多数），两侧都齐全的也是这 169 条。匹配锚点只覆盖口径一的 148 条可用处境，与这 169 条相交 99 条，所以下表的匹配读数与新算的旧读数都取在这 99 条上（同一样本、只有解码不同），可与 169 条上的 0.5330 并存但不相等。

| 水平 | 解码 | 处境数 | 一致率 | 区间 |
| --- | --- | --- | --- | --- |
| base | 0.7 / 0.95 / 320 | 169 | 0.3412 | [0.2840, 0.3984] |
| post | 0.7 / 0.95 / 320 | 169 | 0.2939 | [0.2406, 0.3471] |
| 不带法 DeepSeek（旧刻度，跨协议对照） | 0.0 / — / 600 | 169 | 0.5330 | [0.4714, 0.5962] |
| 不带法 DeepSeek（旧刻度，99 条子集） | 0.0 / — / 600 | 99 | 0.6170 | [0.5387, 0.6970] |
| 不带法 DeepSeek（匹配锚点，同协议） | 0.7 / 0.95 / 320 | 99 | 0.5758 | [0.5051, 0.6431] |
| 带法 DeepSeek（匹配锚点，同协议） | 0.7 / 0.95 / 320 | 99 | 0.5657 | [0.4983, 0.6330] |
| 带法 DeepSeek（参照物本身） | 0.0 / — / 600 | 169 | 1.000 | 定义上 |

口径二不贴地板（base 已有 0.3412 的底子），所以它有分辨力。但同样的协议效应在这里也出现：同在 99 条处境上，旧解码的不带法侧 0.6170 换成匹配解码后是 0.5758（差 −0.0412 [−0.1212, 0.0370]，跨 0），而在匹配锚点内部，**带法 0.5657 与不带法 0.5758 分不开（差 −0.0101 [−0.0842, 0.0640]）**。这个口径在匹配解码下同样分辨不出法的作用。

适配器在文字层没有变像：Δ 的区间跨 0，既不能说变像，也不能说变更不像（结论 3）。

### 口径三：动作可比子集一致率（子集 n 见下表，两侧不同）

| 子集 | 处境数 | 一致率 | 区间 | 可作结论 |
| --- | --- | --- | --- | --- |
| base 侧有可解析动作 | 23 | 0.0145 | [0.0000, 0.0435] | 否（低于 30 条阈值） |
| post 侧有可解析动作 | 137 | 0.1046 | [0.0657, 0.1484] | 是（单侧读数） |
| 两侧都可比的配对子集 | 22 | base 0.0152 / post 0.1212，Δ 0.1061 | Δ [0.0303, 0.1818] | 否（低于 30 条阈值） |

这个口径**没有**不带法 DeepSeek 的读数：旧 `bare` 抽样与匹配锚点都没有在可比子集上另算，这是缺的值，不拿 0 或别的处境的值顶替。

### X

    X = (post_mean − base_mean) / (1 − base_mean) = (0.0968 − 0.0023) / (1 − 0.0023) = 0.0948，区间 [0.0564, 0.1332]

`X_status: defined`。base 侧口径一是 0.0023，所以分母 `1 − base = 0.9977`，**X 实际就是 post_mean 本身**（0.0948 与 0.0968 的差就是那个分母）。这意味着 X 在这份数据上没有独立的含义：它读作「适配器回得多像带法 DeepSeek 的动作」，而这份相似里格式与决策混在一起，所以 X 不能单独当「决策进步」的证据。`X_near_ceiling: false`，`X_replicates_undefined: 0`。

### 格式项与决策项分解（n_pairs = 148，每侧 444 条回答）

| 量 | base | post |
| --- | --- | --- |
| P：回答里有可解析动作的比例 | 0.0563（25 / 444） | 0.7523（334 / 444） |
| A：有动作的回答里吻合的比例 | 0.0400（1 / 25） | 0.1287（43 / 334） |
| 一致率 P × A | 0.0023 | 0.0968 |

| 项（中点约定） | 值 | 区间 |
| --- | --- | --- |
| Δ = post − base | 0.0946 | [0.0586, 0.1351] |

| 决策项 (A_post − A_base)·P̄ | 0.0359 | [−0.0007, 0.0658] |
| `format_share` = 格式项 / Δ | 0.621 | — |
| 残差 Δ − 格式项 − 决策项 | 6.9e−18 | — |

| 项（以 base 为起点） | 值 | 区间 | 占 Δ |
| --- | --- | --- | --- |
| 格式项 ΔP·A_base | 0.0278 | [0.0000, 0.0985] | 29.4% |
| 决策项 ΔA·P_base | 0.0050 | [−0.0001, 0.0099] | 5.3% |

两种拆法在真实数据上都精确闭合（残差 1e−15 内）。中点约定给出 62.1% / 37.9%，但这个 37.9% 里有一半是交互项分过去的（ΔP·ΔA/2 = 0.0309），决策项本身的独立份额只有 5.3%。从 base 起点的视角看，**这次提升的 65.3% 是交互项**：base 侧 P = 5.6%、A = 4.0%，几乎什么都没写、写了也不对，两件事同时变才能产生这一份，把它归给格式或决策任何一边都是约定产物。

所以只报 62/38 会把「主要是学会写工具行」说得比数据能支持的更确定。能确定的只有两件事：P 从 5.6% 到 75.2% 是硬变化（不依赖参照物）；A 从 0.0400 到 0.1287（25 → 334 条有动作的回答里 1 → 43 条命中）方向为正，但它的份额随约定在 5.3% 到 37.9% 之间变，区间下界贴 0。

### 结论

1. **主指标的提升方向是稳的（Δ = 0.0946 [0.0586, 0.1351]，n_pairs = 148），但份额依赖约定。** 回答里有可解析动作的比例从 0.0563 涨到 0.7523（不依赖参照物的硬变化）；中点约定下格式项 0.0587（62.1%）、决策项 0.0359（37.9%），以 base 为起点时格式 29.4% / 决策 5.3% / 交互项 65.3%。两个视角都精确闭合，不存在与约定无关的「格式占几分」。
2. **不能断言「写了动作之后选得更对」。** 决策项的独立份额 0.0050（5.3%）或按中点约定的 0.0359（37.9%），区间下界都贴 0（[−0.0001, 0.0099] 与 [−0.0007, 0.0658]）；方向为正，但这份数据分不出它与 0。
3. **口径二「决策变像了」这个改善不被支持。** 文字层决策签名一致率 Δ = −0.0473，区间 [−0.1085, +0.0118]（配对 169 条）。区间跨 0，所以：**能排除**的幅度是「改善超过 +0.0118」（约 1.2 个百分点）与「变差超过 −0.1085」（约 10.9 个百分点）；**不能排除**的是这之间的一切——小幅改善、0、以及小幅变差，也包括点估计那一个 −0.0473。读作「不支持改善」，不读作「否掉了改善」：点估计方向为负，但负的那一侧同样未达显著。一个在格式上从 5.6% 走到 75.2% 的适配器，在文字层决策形状上没有得到「更接近带法 DeepSeek」的证据。
4. **口径三（已在写工具行的回答里选得对不对）样本不足，只能给方向**：配对子集 22 条处境、Δ = +0.1061 [0.0303, 0.1818]，区间不跨 0，但 22 < 30 条阈值，按规则不作结论；单侧 post 0.1046 [0.0657, 0.1484]（137 条）也只是单侧读数。
5. **同协议下的差距：适配器 0.0968，不带法强模型 0.2815，差 0.185。** 旧的不带法刻度 0.3502 与 base/post 跨两套解码，不能直接相减；它高出同协议读数 0.0687 [0.0146, 0.1239]，这一份是解码效应。换成同协议读数后「离一个没读法的强模型还差一截」仍然成立，幅度从 0.254 降到 0.185。口径二的同协议读数：适配器 0.2939，不带法 0.5758（同在 99 条处境上），方向相同。
6. **这把尺子在 0.28–0.33 这个位置上量不出法的作用。** 匹配解码下，带法侧 0.3311、不带法侧 0.2815，差 0.0496 [−0.0068, 0.1059]；文字层带法 0.5657、不带法 0.5758，差 −0.0101 [−0.0842, 0.0640]。两个区间都跨 0——带法 DeepSeek 在 temp 0.7 下对自己的 0.0 多数签名也只有 33% 的复现率，参照物本身的不稳定把可分辨的差异吃掉了。所以不要把 X 或与不带法刻度的差读成「补上了多少法条效果」：尺子连法本身都量不出。

### 能说明什么

- 窄版适配器在 148 条参照物可用的处境上，把「写不出可解析工具行」这件事改掉了：P 从 5.6% 到 75.2%，这是不依赖评委的可数对照，同向且幅度大。
- 动作签名一致率相对训练前基座的提升方向是稳的（区间不跨 0，n_pairs = 148 ≥ 60 的可用门槛）。
- 两种拆法都报了：中点约定 62.1% 格式 / 37.9% 决策，以 base 为起点时 29.4% / 5.3% / 65.3% 交互项。读的人可以直接看到「份额依赖约定」这件事，而不是拿到一个看起来确定的分数。
- 两个更细的口径（文字层决策、动作可比子集）都指向同一件事：这次 SFT 学到的是「开始写工具行」，不是「决策选得更对」。文字层那个是「不支持改善」，不是「否掉改善」。
- 同一个解码下的对照（匹配锚点）给了两个额外的实数：不带法强模型同协议 0.2815，带法侧同协议 0.3311。

### 不能说明什么

- **不能外推到全部 242 条处境。** 94 条处境的带法动作参照物定不下来（54 条空、40 条没有多数），在它们上面没有任何一致率数字。若这 94 条的行为与 148 条不同，全域结论会偏，偏的方向未知。覆盖率 0.612 是这份测量的边界，不是可以乘上去的系数。
- **口径三不能引用**：base 侧 23 条、配对 22 条，都低于 `MIN_CONCLUSIVE_SITUATIONS = 30`，按规则只作参考。
- **口径二只能否证，不能单独肯定。** 参照物里 64.5% 是单一特征签名（其中 `artifacts` 单独一种占 82 / 169），在这些处境上「一致」只意味着两侧都只给了可核对产物，不说明决策对。
- **X 在这份数据上不是独立信息**：base 口径一 ≈ 0，X ≈ post_mean，格式与决策混在里面。匹配锚点没有也不应该改变 X（X 只用 base 与 post，X = 0.0948 [0.0564, 0.1332] 不变）；它改的是不带法刻度，而刻度变动的方向不是让 X 更有意义，而是暴露了尺子的分辨力。
- **参照物的 1.000 是定义，不是测量。** 同协议下可测的带法侧只有 0.3311（口径一）/ 0.5657（口径二）。引用「离带法 DeepSeek 差 90 个百分点」会把参照物的定义值当成实测天花板，正确读法是对 0.3311 比。
- **匹配锚点只覆盖 148 条，不覆盖口径二的 169 条全集**，所以口径二的匹配读数只算在 99 条相交处境上；那 99 条不等于 169 条，不可把 0.5758 当成 169 条上的刻度。口径三根本没有不带法读数，依然是缺的值。
- **一致率不是正确率**：参照物是带法 DeepSeek 的多数签名，不是正确答案。本文所有数字读作「像不像带法 DeepSeek」，不读作「做对了多少」。整体是否更强由 benchmark 工作包回答。
- **本地侧 30 条回答被 max_new_tokens 截断，匹配锚点 11 条触顶 320**（888 条里，`finish_reason: length`），它们按原样进入统计；截断只会压低命中率，压制幅度未测。

## 修掉的问题（原来错在哪）

1. **预备数据被报成「零处境」并覆盖终版路径**：原 `--analyse --allow-partial` 只保留两侧都齐全的处境，只有 base 数据时 `situations_complete: 0`，所有统计都是 null，而且它照样写 `summary.json` 与 `per-situation.jsonl`（0 行）——终版证据路径被预备状态静默吃掉。现在预备分析写 `preliminary.json` / `preliminary-per-situation.jsonl` 并标 `status: preliminary`。终版闸门看的是「两侧都生成齐全的处境数 = 242」（`generation_complete`），不再看「配对处境数 = 242」——后者永远不成立，因为参照物可用是有条件的（这里 148 / 242），拿它当闸门等于终版路径永远写不出来。生成没跑满时 `--analyse` 默认拒绝写终版，加 `--allow-partial-pairs` 才在两侧已齐全的子集上写，输出照样强制带 `n_pairs` 与 `coverage`，并带 `n_pairs_insufficient`（`n_pairs < 60` 时为 true）。
2. **除零**：原 `rate([])` 是 `sum/len`，任何一侧抽样为 0 条就抛 `ZeroDivisionError`（生成中途、某一侧整体缺失都会触发）。现在空列表返回 None，缺失与 0 分开。
3. **X 算成了错的估计量**：原实现按处境各算一条 `(post - base) / (1 - base)` 再取平均，`base = 1` 的处境要整条丢掉，且单处境比率在 3 条抽样下抖动极大。用任务给的三组期望检验就对不上。现在 X 是先配对求两侧均值再算比率（见口径）。
4. **空参照物造成假命中**：densify 的 law 条件里 54 条处境的多数签名是空，原来拿它当参照物，基座「同样不说话」就被记成命中 → `base = 1.0`，X 因分母为 0 无定义。这是把「两侧都没动作」读成「学会了动作」，会系统性地高估基座。
5. **没有多数也被当成多数**：40 条处境 law 侧 3 条抽样两两不同，原 `majority()` 用「平局取先出现」硬给一个签名并称之为多数，模块 docstring 还写着「带法 DeepSeek 在带法条件下自己和自己一致，所以是 1.0」——这句话在真实数据上不成立。现在票数 < 2 的处境排除并计数，`law_deepseek = 1.0` 只在「表里那条处境参照物可用」的范围内成立。
6. **纯本地分析要导入整套推理栈**：原模块顶层 `import torch` 与 `from transformers import AutoModelForImageTextToText`，`--analyse` 明明不碰模型，却要加载推理栈（本机约 11 秒），且 transformers 版本没有 `AutoModelForImageTextToText` 时分析直接崩。现在只在 `load_pair` / `generate` 里导入，分析 1 秒内跑完，也不碰 GPU。
7. **重复行与半截处境污染分母**：同一 `(model, situation, draw)` 写两次会让「3 条齐全」判假，整条处境被静默当成缺失；某一侧只有 1–2 条抽样时 `0/1` 会被当成真实一致率进均值。现在按 draw 去重并计数，只有 3 条齐全的一侧才给一致率，半截处境单独报出。
8. **主指标被当成决策质量的单一读数**：口径一以「回答里先出现可解析工具行」为前提，而训练前基座只有 5.6% 的回答有这个前提（`base_emits_action` 0.0563），于是 base 贴 0，而 0 里混着「不会写工具行」与「写了也不对」。这个错不在代码在读数，所以修法是把两个与工具语法无关/只比可比子集的口径与一个格式/决策分解加进同一份输出，并在本页写清三个口径各自的含义；口径一本身保持不变（`eval/judge.py` 的判据不改，只调用）。
9. **跨协议比较被当成同一把尺子**：不带法刻度 0.3502 来自 temperature 0.0、max_tokens 600、每条件 3.04 条抽样，base/post 是 temperature 0.7、top_p 0.95、max_new_tokens 320、3 条，两者被直接相减。现在 `scripts/measure_anchor.py` 用 base/post 那套参数与同一条 prompt（逐条 sha256 核对）重抽了 148 条处境的带法/不带法两侧（888 次调用、¥0.7115），不带法刻度改成同协议的 0.2815，旧的 0.3502 作为跨协议对照保留，两者之差单独报（0.0687 [0.0146, 0.1239]）。同时报出参照物的 1.000 是定义、同协议可测的带法侧是 0.3311。
10. **结论超出证据**：「口径二否掉了改善」建立在 Δ = −0.0473 上，而它的区间 [−0.1085, 0.0118] 跨 0，能排除的只是「改善超过 1.2 个百分点」，不是「改善」本身。现在写成「不支持改善」，并写出区间能排除与不能排除的幅度。
11. **一种分解被当成唯一分法**：中点约定下的 62.1% / 37.9% 被读成真实份额，而把同样精确的以 base 为起点的拆法列出来，交互项 ΔP·ΔA = 0.0618 占 Δ 的 65.3%，交互项吃掉了中点「决策项」的一半。现在 `decomposition()` 同时输出 `format_part_at_base` / `decision_part_at_base` / `interaction_part` 与各自的区间，`--check` 两种拆法都断言，本页两个视角并列。

## 自检

`python3 scripts/measure_actions.py --check` 用假回答走真路径（动作解析 → 每处境一致率 → 两侧均值 → X → 按处境配对自举），再跑两组只动一个变量的假数据验分解，结果落 `evidence/measure/selftest.json`：

口径一（X 与区间）：

| 组 | base / adapter | X | 区间 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | 0.2 / 0.6 | 0.5 | [0.306, 0.677] | 通过 |
| 2 | 0.9 / 0.95 | 0.5 | [0.000, 1.000] | 通过 |
| 3 | 0 / 0 | 0 | [0.000, 0.000] | 通过 |
| 4 | 1 / 1 | 无定义 | 无 | 通过 |

第 2 组的区间 [0, 1] 就是「base 接近 1」的形状：头部空间只有 0.1，比率被放大 10 倍，点估计可用而区间几乎无信息。第 3 组 X = 0 是按本页公式算的（分母 `1 - 0 = 1`，有定义）——「无定义」的情况是 base = 1（第 4 组，分母 0，2000 次重抽全部无定义），不是 base = 0。

格式/决策分解（两组只动一个变量，每组 40 条处境 × 3 条 = 120 条回答）：

| 组 | 动的变量 | base（P / A） | adapter（P / A） | Δ | 格式项 | 决策项 | `format_share` | 判定 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 5 | 动作比例 0.05 → 0.5，吻合率不变 0.5 | 0.05 / 0.5 | 0.5 / 0.5 | 0.225 | 0.225 | 0.000 | 1.00 | 通过：提升纯来自格式 |
| 6 | 动作比例不变 0.5，吻合率 0.3 → 0.9 | 0.5 / 0.3 | 0.5 / 0.9 | 0.300 | 0.000 | 0.300 | 0.00 | 通过：提升纯来自决策 |

自检只证明 X、区间与格式/决策分解的算术：它不证明动作解析器或文字层判据的判定质量，不证明口径二的签名在语义上真的代表“决策”，也不证明抽样本身。中点与 base 起点两种拆法都在同一批假数据上断言（`format_part` / `decision_part` / `residual` 与 `format_part_at_base` / `decision_part_at_base` / `interaction_part` / `at_base_residual`），并断言中点约定确实把交互项平分成两半（`interaction_part / 2` 等于中点格式项减去 ΔP·A_base）。

## 还缺什么

- 94 条处境没有可用的动作参照物（54 条空、40 条没有多数），在它们上面没有任何一致率数字，本页结论只覆盖 148 条。要给全域结论，先得给这 94 条定义参照物（例如改比「law 抽样里出现过的动作集合」而不是单点多数），并接受参照物变松后 `law_deepseek = 1.0` 的含义跟着变。
- 口径二的参照物区分力弱：64.5% 是单一特征签名，其中 82 / 169 只剩 `artifacts`。要让口径二能正面支撑「决策变像了」，要么把文字签名做细（「停住」再分停在授权门与停在自查门，或引入动作方向而不只记动作有无），要么只引用参照物为两特征及以上的那 35.5% 处境上的读数并给出该子集的区间。现在它只能否证。
- 口径三的 base 侧只有 23 条处境、配对 22 条，低于 30 条阈值。这条口径要能作结论，得先有更多「基座也写了工具行」的处境，否则它永远只测得到 post 一侧。
- **匹配锚点只覆盖 148 条**：口径二的 99 条相交子集上有了同协议读数，但剩下的 70 条仍只有旧解码的刻度；口径三依然没有不带法读数。要把两个细口径都放到同一把尺子上，得按口径二、口径三各自的处境集各再抽一批（按同一条构造，每批≤ 800 次调用）。
- **参照物本身的不稳定是现在最大的约束**：带法 DeepSeek 在 temp 0.7 下对自己的 0.0 多数签名只复现 0.3311，于是「带法对不带法」的差只有 0.0496 且跨 0。要让尺子量得动法的作用，得把参照物从「一个固定签名」换成「一个分布」（例如按签名比对带法/不带法两组抽样的重叠，或把参照物自己也在每套解码下重抽）——这是口径的变更，不是调一个参数。
