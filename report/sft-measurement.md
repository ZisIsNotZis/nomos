# 窄版适配器的动作一致率测量：预备

状态：**预备**。adapter（`post`）侧抽样还在生成，`X` 不可算；本页的数字只说明口径与 base 侧事实，不许当结论引用。终版输出是 `evidence/measure/summary.json`，只有 242 条处境两侧各 3 条齐全时 `scripts/measure_actions.py --analyse` 才会写它。本次预备快照见 `evidence/measure/preliminary.json`（`status: preliminary`）。

## 口径

### 处境与 prompt

242 条处境 = `evidence/slice-contrast/situations.jsonl` 的 183 条 + `evidence/grow/situations.jsonl` 的 59 条，id 固定。每条处的 prompt 是处境原文 `excerpt` 接上 slice-contrast 的续写指令，**不含任何法条原文**：生成前用 `build_sft.law_phrases()` 的 175 条短语逐条查过，命中即停。三个水平（训练前基座 base、窄版适配器 post、参照物带法 DeepSeek）共用同一个 prompt 与同一套解码，每处境各抽 3 条（temperature 0.7、top_p 0.95、max_new_tokens 320）。

### 动作签名怎么取

每条回答经 `eval/judge.py` 的 `parse_actions` 抽出所有 `tool: name(args)`，再由 `resample_actions.signatures` 压成签名元组：`bash` 记 `bash` 加规范化后的命令，读写类工具记工具名加目标路径，其余只记工具名。签名是**有序元组，全等才算命中**——回答里多一个动作、少一个动作、动作顺序不同都算不一致。回答里一个可解析动作都没有时签名是空元组，它不是一条动作，也不是缺失值。

### 与哪一侧比

比的是**带法 DeepSeek 的多数签名**（`evidence/densify/answers.jsonl` 的 `law` 条件，每处境 3–4 条抽样），即「读了法之后的动作」。选它作参照物是因为它自己和自己最一致，不是因为它是对的。不带法 DeepSeek（同一批 `bare` 抽样）用来给参照物标一个刻度：一个没读法的强模型有多大概率自己说中。

参照物只在两个条件同时成立时才算**可用**：

- **定下来了**：law 条件里出现次数最多的签名至少拿到 2 票。3 条抽样两两不同时票数是 1，那不是一个多数，只是第一个出现的签名，把它当参照物等于把噪声当答案。
- **非空**：多数签名本身含至少一个动作。空签名当参照物时「基座也什么都没说」会被记成命中，这是把「两侧都没动作」当成「学会了动作」。

两者之一不成立的处境**不计入一致率**，并分别计数报出（`reference_selection`）。

### 一致率的分母

每处境每侧的一致率 = 该侧 3 条抽样里签名等于参照物的条数 / 3；某个侧只有 1–2 条抽样时**不给一致率**（半条处境的 0/1 会被当成真实比例），该处境在这一侧记为缺失并单独计数（`situations_base_partial`）。跨处境的一致率 `base_mean`、`post_mean` 是可用处境上的一侧一致率的算术平均，分母是可用处境数。

### X 的定义

X 是「适配器补上了多少法条带来的剩余空间」：

    X = (post_mean - base_mean) / (1 - base_mean)

`base_mean` 与 `post_mean` 取**两侧都齐全的同一批可用处境**（配对）。先算两侧均值再算比率，不是先按处境各算一条 X 再平均：单处境 X 在 `base = 1` 时无定义，逐条平均就必须把那些处境整条丢掉，均值因此有偏；而 3 条抽样下单处境一致率只能取 0、1/3、2/3、1，比率抖动极大。逐处境的 `X_situation` 只作诊断列输出在 `evidence/measure/per-situation.jsonl`，不进 X。

### 区间怎么算

配对自举，**重抽单位是处境**，不是抽样条数：每次从配对处境里有放回抽 n 条处境，同一批处境的两侧一致率一起进来（base 与 post 的相关性保住），重算 `base_mean`、`post_mean`，再算该次重抽的 X。2000 次重抽取 2.5% / 97.5% 分位作区间。某个重抽样本里 `base_mean` 恰好等于 1 时，该次的 X 无定义，跳过并计入 `X_replicates_undefined`；全部重抽都无定义时区间是 null。

### base 接近 1 或 0 时

- **`1 - base_mean = 0`（base 已经满分）**：X 无定义，报 `X_status: undefined_no_headroom`，也不给区间——剩余空间是 0，比率没有意义。绝不返回一个补丁值。
- **`1 - base_mean` 很小**：X 照算，但同时报 `X_near_ceiling: true`（阈值 0.2）与 `X_headroom`。空间小则同样的差值被放大，区间会很宽，读的时候必须带区间而不是只看点估计。
- **`base_mean = 0`**：X 有定义，等于 `post_mean`（分母是 1）。此时 X 与原始一致率同义，「补上剩余空间的比例」这个含义消失，报告里要说明是这一种情况。
- 生成尚未完成时（`post_mean` 缺失）X 一律是 null，`X_status: undefined_adapter_side_missing`，不当 0 处理。

### 可数对照

另外报一个不经评委、不看参照物的量：回答里有没有至少一个可解析动作（签名非空）。它只说明模型「说不说话」，不说明说得对不对，用来把「一致率高」与「动不动手」分开。

读法：在参照物可用的处境上，训练前基座 99 条处境里**一条都没命中**带法 DeepSeek 的多数动作，而且只有约 6% 的回答里出现任何可解析动作——82 条处境三次抽样全不说话，17 条说了但说的是别的动作。所以 base 侧的地板基本在 0，X 一旦能算就会接近 `post_mean` 本身。这个 0 是「3 条抽样全部不命中」的离散结果，不是真值 0；区间 [0, 0] 只反映自举在 n=99 上没抽到命中，不能读成「基座精确为零」。

参照物本身的分辨率也要带上：242 条处境里只有 148 条的动作签名定得下来，也就是说这条测量的结论最多覆盖 148/242 条处境，剩下 94 条的参照物是空动作或没有多数，它们的一致率不进任何分子分母。

## 修掉的问题（原来错在哪）

1. **预备数据被报成「零处境」并覆盖终版路径**：原 `--analyse --allow-partial` 只保留两侧都齐全的处境，只有 base 数据时 `situations_complete: 0`，所有统计都是 null，而且它照样写 `summary.json` 与 `per-situation.jsonl`（0 行）——终版证据路径被预备状态静默吃掉。现在预备分析写 `preliminary.json` / `preliminary-per-situation.jsonl` 并标 `status: preliminary`，数据不全时终版 `--analyse` 直接拒绝写。
2. **除零**：原 `rate([])` 是 `sum/len`，任何一侧抽样为 0 条就抛 `ZeroDivisionError`（生成中途、某一侧整体缺失都会触发）。现在空列表返回 None，缺失与 0 分开。
3. **X 算成了错的估计量**：原实现按处境各算一条 `(post - base) / (1 - base)` 再取平均，`base = 1` 的处境要整条丢掉，且单处境比率在 3 条抽样下抖动极大。用任务给的三组期望检验就对不上。现在 X 是先配对求两侧均值再算比率（见口径）。
4. **空参照物造成假命中**：densify 的 law 条件里 54 条处境的多数签名是空，原来拿它当参照物，基座「同样不说话」就被记成命中 → `base = 1.0`，X 因分母为 0 无定义。这是把「两侧都没动作」读成「学会了动作」，会系统性地高估基座。
5. **没有多数也被当成多数**：40 条处境 law 侧 3 条抽样两两不同，原 `majority()` 用「平局取先出现」硬给一个签名并称之为多数，模块 docstring 还写着「带法 DeepSeek 在带法条件下自己和自己一致，所以是 1.0」——这句话在真实数据上不成立。现在票数 < 2 的处境排除并计数，`law_deepseek = 1.0` 只在「表里那条处境参照物可用」的范围内成立。
6. **纯本地分析要导入整套推理栈**：原模块顶层 `import torch` 与 `from transformers import AutoModelForImageTextToText`，`--analyse` 明明不碰模型，却要加载推理栈（本机约 11 秒），且 transformers 版本没有 `AutoModelForImageTextToText` 时分析直接崩。现在只在 `load_pair` / `generate` 里导入，分析 1 秒内跑完，也不碰 GPU。
7. **重复行与半截处境污染分母**：同一 `(model, situation, draw)` 写两次会让「3 条齐全」判假，整条处境被静默当成缺失；某一侧只有 1–2 条抽样时 `0/1` 会被当成真实一致率进均值。现在按 draw 去重并计数，只有 3 条齐全的一侧才给一致率，半截处境单独报出。

## 自检

`python3 scripts/measure_actions.py --check` 用假回答走真路径（动作解析 → 每处境一致率 → 两侧均值 → X → 按处境配对自举），结果落 `evidence/measure/selftest.json`：

| 组 | base / adapter | X | 区间 | 判定 |
| --- | --- | --- | --- | --- |
| 1 | 0.2 / 0.6 | 0.5 | [0.306, 0.677] | 通过 |
| 2 | 0.9 / 0.95 | 0.5 | [0.000, 1.000] | 通过 |
| 3 | 0 / 0 | 0 | [0.000, 0.000] | 通过 |
| 4 | 1 / 1 | 无定义 | 无 | 通过 |

第 2 组的区间 [0, 1] 就是「base 接近 1」的形状：头部空间只有 0.1，比率被放大 10 倍，点估计可用而区间几乎无信息。第 3 组 X = 0 是按本页公式算的（分母 `1 - 0 = 1`，有定义）——「无定义」的情况是 base = 1（第 4 组，分母 0，2000 次重抽全部无定义），不是 base = 0。

自检覆盖的是 X 与区间的算术；它不证明动作解析器的判定质量，也不证明抽样本身。

## 还缺什么

- adapter（`post`）侧 242 × 3 条抽样。现在 `situations_paired = 0`，X 与区间都算不出来。
- base 侧 242 条全部齐全（预备快照里 169 条），否则配对处境数少于 242，X 覆盖的不是全部处境。
- 148 条可用参照物之外那 94 条的处理方式还没有定论：它们的一致率不进分子分母，报告必须把结论限制在 148 条上，或者另行想办法给它们定义参照物。
