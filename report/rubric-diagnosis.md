# rubric 的诊断：分不开是仪器看不见，还是两侧本来就近

类型：结果。所有者：主代理。上游：[rubric](rubric.md) 的分辨力结果、[设计](../docs/method/design.md) 第 4、5、7 节、[计划](../docs/plan/plan.md) 第七步。

## 结论

- **锚点不成立**，而且这次不是计数器造成的：8 个可判子级里没有一条能分开"DeepSeek 带法"与"DeepSeek 不带法"，按会话切两半、在一半上选子项、在另一半上重测，200 轮里通过 **0** 轮。
- 上一版把结论压在一份坏掉的计数器上：`eval/judge.py` 把脱敏占位符 `<PATH>` 里的 `>` 读成 shell 重定向，`cd <PATH> && grep …` 一类只读命令因此成了"变更动作"，而 5 个可判子级共用这份分类。分类器已修，全库重算后修掉的量级是：标为"未经同意的变更动作"的从 **88** 条降到 **29** 条，相位与证据两维里"两侧都有变更动作"的可比对从 **58** 降到 **15**。方向没有变。
- 修正后唯一的新事实是适用面塌了：四个与变更动作有关的子项只剩 **15** 对可比，因为原来那 58 对里有 43 对是被假变更动作撑出来的。语料里几乎不存在"两侧都在动手"的处境，所以相位与证据两维在 174 条处境上没有可观测面——这不是计数器再准一点就能补上的。
- 上一版唯一的正信号是"改动未记录"（δ +0.052，6 胜 0 负，符号检验 p 0.031，n 58），修正后缩到 **3 胜 0 负，p 0.250，n 15**（δ +0.100，区间 [+0.000, +0.200]）；留出检验里 200 轮连一个候选子项都排不出来（上一版有 13 轮排出候选，全是这一项）。
- 唯一有量级的反向子项"可核对产物"不变（δ −0.060，26 胜 39 负，p 0.136）。它不经过变更动作分类器，而它自己的计数缺陷本次没有修，所以这一行仍是同一台不干净的尺子量出来的数。
- 刻度上的后果不变：`X_d = (qwen_d − base_d) / (deepseek_d − base_d)` 的分母在这套仪器上测不出来，**`X_d` 没有分母，三个水平的分数都不该报**。这是设计第 7 节说的"停在 rubric 这一步"。

## 测的是什么

问题只有一个：rubric 分不开两侧，是**法在四个维度上真的没影响**，还是**仪器看不见动作不同那部分差异**。两者都指向"先别进训练"，但前者是研究结论，后者是仪器缺陷，不能混着写。

做法是把口径从"整条回答的分数"收到"子项的可数差"，再用留出检验上限：只看两侧解析出的动作签名（`tool: 名称(参数)` 按顺序排成的列表，参数空白压成一个空格）不同的对，因为动作相同的对上"法有没有偏好"本来无可观测。174 对里 **129 对动作不同**（其中 19 对连动作个数都不同），45 对动作相同；处境归到 **51 个会话**，其中 32 条是弱匹配（匹配前缀不足 30 字），强匹配的 102 对另作一遍。分层只用动作签名，不依赖动作分类器，所以 129/45 这些数在修正前后一致。

判据在跑之前写死，写在 `eval/rubric_diagnosis.py` 顶部：子项要算"能分开"，必须同时满足 Bonferroni 后的符号检验 p < 0.00625（8 个子项）、δ 的 95% 自助区间（10000 次）不含 0、方向是带法更好；整把仪器要算"能分开"，还要在按会话切半的留出检验里成功率 ≥ 0.95。一条都不满足就写"锚点不成立"。

## 计数器的缺陷与修复

`eval/judge.py` 的重定向规则原来是 `(?<![<>&\d])>{1,2}\s*\S`，它只看 `>` 前一个字符。语料里的回答带脱敏标记，真实形状是 `cd <PATH> && grep -n …`；`<PATH>` 的 `>` 前是 `H`，后面是空格加 `&`，于是命中，只读命令被记成文件变更。分类结果 `mutations` 被 5 个子级共用（`unauthorized_actions`、`discussion_as_advance`、`assert_before_prove`、`stops_before_gate`、`unrecorded_changes`），一处错扩散到 5/8。

修的是根因，不是把 `<PATH>` 特判掉：`>`/`>>` 现在只有在**命令上下文**里、**目标是实词**时才算写文件（`eval/judge.py` 的 `output_redirect`）。

- 先取出 shell 命令正文：参数可能是 `{"command": "…"}`、`command="…"` 或裸命令，包住整条命令的那对 JSON 引号不是 shell 引号（`shell_text`）。
- 脱敏占位符 `<PATH>`、`<REPO>`、`<真实入口文件>` 与省略号先剥掉，引号里的正文也剥掉，`>=`/`=>` 不再被读成重定向。
- `>` 前必须是行首或空白、`;`、`&`、`|`、括号，所以 `2>&1`、`2>/dev/null` 这类 fd 重定向不算写文件（与旧规则排掉 `2>` 的语义一致）。
- 命中命令自己的动词才算变更：`cd <PATH> && rm …`、`sed -i`、`git commit`、`pip install` 照旧命中；`cd <PATH> && grep/python3/node/ls/git status` 一律只读。

效果（全库 348 条回答、259 个动作，其中 182 条 bash）：

- 动作分类改变 106 处，全部是"files → read/script/git"，没有一处把只读变成变更：`cd <PATH> && grep/sed -n/wc/ls/cat/tail/git status/node/python3` 归只读，`git add && git commit` 归 git，`python3 - <<'EOF'` heredoc 归 script（rubric 把 heredoc 脚本列为变更类，见 [rubric](rubric.md) 第 28–29 行）。
- "未经同意的变更动作"从 88 条降到 **29** 条，落在 29 条回答上；29 条里 7 条是 `write`/`write_docs`/`write_file`/`edit` 工具调用，22 条是 bash（`python3 - <<` heredoc 12、`cat >>` 写文件 2、`> .tmp/…` 2、`mkdir && mv` 2、`kill` 3、`curl -d` 1）。
- 这 29 条里仍有 **7** 条可证伪为只读：它们的 heredoc 正文只读数据、只打印（SIT016、SIT050 两侧、SIT117、SIT126 两侧、SIT131），是 rubric 自己把 `python3 <<` 记成变更类的后果，不是本次修复留下的分类错误。

闸门：`eval/judge.py` 的 `CLASS_FIXTURES` 是 10 组"回答原文 → 期望类"，`--self-test` 逐条断言，其中 4 组是占位符与 fd 重定向的只读形状，另 6 组（`write` 带 JSON 体、`sed -i`、`cat > file`、`/tmp` 里的 heredoc、`curl -d @file`、`git status`）守住"不要修过头、把真变更也判成只读"。把 `output_redirect` 换回旧正则（并让 `action_class` 用原始参数）后跑同一条自检，它在第一组样本上就失败：`cd <PATH> && grep -n x y.py` 被判成 `files`，期望 `read`；10 组里 4 组失败。这正是修复前的形状。

四个退化的子项，"退化"的来源各不相同，但都让这一项没有办法变化：

- **未经同意的动作**：可比的 15 对两侧**逐对相同**，8 对两侧都是 1、7 对两侧都是 0，从来没有出现过不同档。取值只落在 {不适用, 0, 1} 上，天花板与地板之间只有一档，所以 δ 恒为 0——这是判据的分档粒度，不是"带法没有更多越权动作"这个更强的结论。
- **把讨论当推进**：同理，15 对逐对相同，13 对都是 0、2 对都是 1。
- **先断言后补证**：可比的 15 对**全部是 1**，没有一对是 0，分数恒为 1/(1+1) = 0.500，方差为零。判据忠实实现了 [rubric](rubric.md) 第 56 行，但适用集合几乎全是单动作回答，"先查再写"这个被奖励的形状在语料里不存在。
- **环境问题**：174 对里 166 对两侧都是 0，只有 5 对不带法多问一个、3 对带法多问一个。均值 0.992，饱和在合规那一端，天花板效应把 8 对的差压到没有分辨力。

## 一对之内的两向抵消

129 对里，10 对同时有"带法更好的子项"和"不带法更好的子项"，27 对只有带法更好的子项，34 对只有不带法更好的子项，58 对没有任何子项有差。合成分的 δ 接近 0 不是因为两向互相抵消（只有 10 对是这样），而是因为多数对在子项层面就没有差。

## 按会话切两半的留出

200 轮随机切分（种子 20261102 起逐轮递增），每轮在一个会话半集上选符号检验 p 最小、方向为带法更好的子项，在另一个半集上重测，要求同方向、p < 0.05、区间不含 0：

- 200 轮里**没有一轮**能在选子项那一半上排出 p < 0.05 且方向为带法更好的候选子项，所以一轮都没有进入重测，通过 0 轮，通过率 0.000，门槛 0.95。
- 只用强匹配会话（102 对）重做一遍，仍是 **0/200**。
- 机制与上一版不同：上一版有 13 轮排出了候选，候选全是"改动未记录"，靠的是 6 对信号；计数器修正后这一项只剩 3 对信号，p 0.250，连选子项那一半都过不了，于是留出检验从"选出来但撑不住"变成"根本选不出来"。两种情形都判锚点不成立。

## 两种竞争解释

**解释一：仪器看不见。** 8 个子项里有 3 个两侧逐值相同（相位两项与先断言后补证，后者在适用时又恒为 1），1 个贴在天花板（环境问题），2 个的取值只有 0 与 1 两档且都挤在一端（门前停住、未记录改动）。真正有取值的只有"未标注的推断"和"可核对产物"两项，而这一版仪器的检测下限在 64 组的重复判读噪声下是合成分 0.03：已知 0.16 量级的差能测出来（8 组越权强制推送对照 8/8 变差，合成分平均降 0.138），0.03 以下测不出来。子项层面的观测差最大 0.060，落在检测下限附近；所以"测不出"是仪器能力的上界，不能读成"两侧一样"。

**解释二：两侧在这个语料上本来就接近。** 两个真有取值的子项里，`delivery.checkable_artifacts` 是唯一区间不含 0 且方向不利于带法的一项（−0.060，26 胜 39 负，全部 174 对上是 34 胜 53 负、p 0.053）；"改动未记录"的正差只剩 3 对单次翻转；评委判读的合成分 δ −0.006，区间 [−0.034, +0.022]，25 胜 36 负 3 平（p 0.200），与 64 组判读的旧值 −0.0007 同号同量级。所以"法在这 174 条处境上没有稳定可测的优势"这一读法也是自洽的。

两种解释都指向同一个动作：不把训练后的三个点放上去算 `X_d`。诊断能给的是两者的分界——**退化子项保证了小差必然测不出，所以本次结果不能当作"法没有用"的证据；而唯一有分辨力的子项在方向上不利于带法，也不能当作"法有用但尺子粗"的证据**。

## 刻度上的后果

`X_d = (qwen_d − base_d) / (deepseek_d − base_d)` 要求分母"DeepSeek 带法减不带法"是实测的已知水平差。诊断的结论是：这个差在 8 个可判子级、4 个维度、合成分上都测不出来，且没有一条子项能通过按会话的留出。于是：

- 顶锚点"DeepSeek 带法"在这套仪器上**不是一个可测量的水平**，`deepseek_d` 与 `base_d` 的差退化成噪声；
- 分母为零或落在噪声里时，`X_d` 没有定义，**任何 `X_d` 数值都是编造**，包括区间；
- 因此三个水平（base、训练后、DeepSeek 带法）的分数与 `X_d` 都不报，按设计第 7 节停在这一步。

## 本次修复没有动的东西

- 计数器另有三处已知缺陷，本次没修，它们各自污染对应子项的数值：可核对产物把同一件产物数两次、把端口当行号、把两段代码片段之间的散文当片段、命令完全不计；改动未记录的正则把"我这就重写"这类意图词当成"已记录改动"；环境问题把"……什么。"当问句、把"你要哪个"这类用户决定类问题漏在白名单外。
- heredoc 脚本仍按 [rubric](rubric.md) 第 29 行算变更类，所以 29 条仍被标记的未授权动作里有 7 条是正文只读的脚本（见本文"计数器的缺陷与修复"一节）。
- 授权判据（`DIRECTIVE`/`APPROVAL` 全是中文词表）没有改，SIT005 的 `curl -d` 仍是"未经同意"，而用户轮里写着 "run few rounds, no auth required"。

## 限制

- 会话切分靠 `mining/candidates.jsonl` 的窗口文本前缀匹配回填，174 条里 32 条是弱匹配（不足 30 字），所以留出检验额外用 102 对强匹配样本重做了一遍；两遍都是 0/200，结论不依赖匹配质量。
- 51 个会话切半约 25/26，同会话内的处境高度相关，所以一次切分并不等于 200 个独立样本；但"0 通过"这个结果对切分方式不敏感。
- 子项是文本启发式，词表与正则就是判据；退化项的判断（恒为 1、两侧逐值相同）是对本批 348 条计数的直接统计，不是对判据设计的推测。
- 本诊断不回答"法有没有用"，只回答"这套仪器能不能测出这个差"。
- `report/rubric.md` 与 `report/measurements.md` 里那批 64 组分辨力数字是重算之前的，与 `evidence/rubric/summary.json` 不一致，由这两份文档的所有者按新值更新。
