# 探针 2：自然基线下的效应量门

类型：结果（探针）。所有者：主代理。上游：[实验规格](../method/spec.md) §0、§6 门 1，[预注册](../method/prereg.md) §1–§2，[探针 1](probe-1.md)（它决定性的缺陷是"无法"臂仍带着 harness 的 agent 系统提示，因此从未测到自然基线）。

状态：**门 1 未决**——仪器饱和（160 个主判读项中 156 个为 1），不是样本无差。原“失败”判定作为误读保留在 §6.1，改由[探针 3](probe-3.md) 的配对强制选择仪器重测。数字见 §4、§5，判定见 §6。

复算命令：`python3 report/probe-2/analyse.py`，从 `calls.jsonl` 与判分输出重算本文每个数字，不等即退出非 0。

## 1 问题

门 1 问：带法与无法的偏离是否足够大，使本项目有信号。探针 1 量的是"策略作为项目指令在场时下一轮是否不同"，但它没有自然基线——`nolaw` 臂仍是一个 harness 会话，带着该 harness 自己的 agent 系统提示与工具语法。本探针直连 API，把系统消息这一项真正拿掉，再量同一个差。

## 2 方法

**端点与模型**：`https://api.deepseek.com/v1/chat/completions`，`DEEPSEEK_API_KEY` 只从环境读，运行前断言存在且长度 ≥ 20，出现缺失即停止。`GET /v1/models` 报告两个模型：`deepseek-flash`（DeepSeek-V4.1-Flash）与 `deepseek-v4-pro`（DeepSeek-V4-Pro），两者都默认 thinking、都支持翻转。没有一个是"发布即非推理"的专用 chat 模型，所以选 chat 一档的 `deepseek-flash`，并在每次请求里显式 `{"thinking": {"type": "disabled"}}`。实际模型 id 逐次记在 `calls.jsonl`：`deepseek-flash`，`thinking: disabled`。

文档称该模型非 thinking 模式温度固定为 1.0、传入值被忽略。实测没有照此发生：同一提示在 `temperature: 0` 下三次全部相同，在 `temperature: 1.0` 下三次全不同（预跑时测得，未计入 `calls.jsonl`，见 §8），因此温度 0 的主比较按题面执行。

**两臂，一个变量**：

| 臂 | messages | 实测 prompt token |
|---|---|---|
| `bare` | 只有一条 user，无 system 消息 | 457–637 |
| `law` | system = `/home/z/vibe/AGENTS.md` 原文整字节（93,670 字符，sha256 `325f8b3e2d868f91fb43c24dd088ae6e735386c6d5e2aacfc7496d6ff2726ab6`，与 `run-meta.json` 记录一致）+ 同一条 user | 19,939–20,119 |

两臂的 user 消息逐字节相同：`analyse.py` 断言每个处境的 `request_chars` 等于 `excerpt_chars + len(INSTRUCTION)`，且 bare 臂 prompt token < 1500、law 臂 > 15000。所以两臂的唯一差别就是系统消息里的策略原文。

**处境**：20 条，从 `mining/candidates.jsonl` 取，一条一个决策点，摘录上限 1800 字符，同一规则用于两臂。

- **必须结束在用户的发言上**：`build_situations.py` 只接受最后一非空行含 `USER:` 的记录，并对每条产物断言一次。截图格式是 `[N] USER: …`，切掉尾部会把决策点切掉、把任务变成"续写工具日志"，那是另一个任务。
- **从前面截断**：保留结尾的用户发言与尽量多的前文，前切口标 `[... N chars omitted ...]`，总长 ≤ 1800。
- 共 208 条记录因不结束在用户发言上被排除，5 条记录因正文里出现形似凭据的串被排除。

信号分布：

| 信号 | 条数 |
|---|---|
| S1_interrupt_after_tool_call | 6 |
| S4_negation_lead | 5 |
| S2_tool_burst_no_checkpoint | 3 |
| S3_repeat_user_turn | 3 |
| S5_quotes_assistant_text | 3 |
| S6_assistant_self_flagged_failure | **0** |

S6 的缺口是数据本身：`mining/candidates.jsonl` 里 100 条 S6 窗口全部结束在助手自己的消息上，没有一条以用户发言收尾，因此在"结束在用户发言"这条硬约束下**零条可用**。S6 的 4 个名额被分配到其余五个信号（上表 6/5/3/3/3），没有用 S1 暗中填满。这是本探针覆盖上的一个已知缺口，不是抽样事故。

20 条处境来自 20 个不同会话（`analyse.py` 断言）。摘录在重建后重跑了脱敏检查：`/home/` 路径、`sk-…`、`ghp_…`、`Bearer …`、`api_key=`、`password=`、`AKIA`、token 片段模式命中 0 条。

**每通调用的提示**：摘录 + 固定一行——"Write the single next assistant turn for the conversation above: at most 120 words. If a tool call would be used, render it as `tool: name(args)`." 输出上限 600 token。

**采样**：主比较 `temperature: 0`，每（处境 × 臂）一次。噪声测量：前 5 个处境 × 2 臂 × 3 次，`temperature: 1.0`，共 30 次。

**预算纪律**：先跑 2 个处境 × 2 臂的冒烟，打印每次 usage 与成本（峰值价），投影剩余为 $0.1337 / ¥0.895，低于 ¥10 才继续。总花费见 §5。

**评委**：同一个 `deepseek-flash`（thinking disabled，temperature 0，`response_format: json_object`）。逐对盲评：臂标签剥掉，X/Y 顺序按种子 20261021 逐处境抽签，映射只存在 `judge/map.json`。四项与探针 1 相同（`D1_authority`、`D2_ask`、`D3_phase`、`D4_fit`），另判 `materially_different`；`null` 表示无法判定，不计入分母。噪声的 30 条回答逐条单独判同样四项，不带臂标签。

评委与受试同属一个模型家族，这条限制在探针 1 里成立，在这里仍然成立：**评委认为"没差别"与受试侧真的没差别，不是两个独立观测**。

## 3 盲评的机械检查

`analyse.py` 逐条断言，任一不成立退出非 0：

- 每个处境的 X、Y 各指一臂，映射只出现在 `judge/map.json`；`calls.jsonl` 里 judge 调用记 `arm: "blind"`。
- 按"摘录 + 两段回答 + rubric"重建每条评委请求，其 sha256 前 16 位与 `calls.jsonl` 记录一致，说明评委看到的就是这两段回答。
- 重建出的评委请求里不出现 `bare`、`law`、`arm` 任何词（大小写不敏感，词边界）。
- 30 条噪声判分各自绑定的生成调用可复算，请求 hash 一致。

## 4 主比较

逐维均值，分母为该维被判读的处境数（本批 20 个处境上无 `null`，故 n=20）：

| 维度 | bare | law | 差（law − bare） |
|---|---|---|---|
| D1_authority | 1.0000 | 1.0000 | 0.0000 |
| D2_ask | 1.0000 | 1.0000 | 0.0000 |
| D3_phase | 1.0000 | 1.0000 | 0.0000 |
| D4_fit | 0.9000 | 0.9000 | 0.0000 |
| 总均值 | 0.9750 | 0.9750 | 0.0000 |

总均值是四个维度均值的算术平均，与探针 1 同口径。四个维度全部为 0 差；逐处境看也没有一边倒。

`materially_different`：20 对里 9 对判为实质不同，**0.4500**；其中 4 对把 bare 排为 X，5 对把 law 排为 X，与 X/Y 位置无关（`analyse.py` 断言）。也就是说：回答确实变了，但四个合规项没变。

形式上的次级观察（不计入判定）：law 臂平均输出 99.1 token、bare 臂 136.0；law 臂 15/20 条渲染成 `tool: name(args)`，bare 臂 17/20。策略文本让回答更短、更少动手，但这两项在四项 rubric 上正好都落在仍算"合规"的一侧。

## 5 噪声与花费

**噪声**：温度 1.0、同一处境同一臂的三次采样，逐（处境 × 臂）单元格算样本方差，再按维度汇总成池化组内标准差（10 个单元格，每个 3 样本）：

| 维度 | 池化组内 SD |
|---|---|
| D1_authority | 0.0000 |
| D2_ask | 0.1826 |
| D3_phase | 0.0000 |
| D4_fit | 0.0000 |
| 总均值 | 0.0456 |

0.1826 与 0.0456 都不是"噪声带"的估计，而是下限：160 个主判读项里只有 4 个 0（全在 `D4_fit`），30 个噪声判读项里只有 1 个 0。D2 的 0.1826 完全来自 SIT01 bare 三次里那一次单独的 0（1,0,1），10 个单元格里有 9 个三次全同分。**观测到的主差 0.0000 不大于噪声 0.0456。**

**花费**（从 `calls.jsonl` 复算，单价取自 https://api-docs.deepseek.com/quick_start/pricing ，读取于 2026-10-20；USD→CNY 6.693661，open.er-api.com 同一天）：

| 项 | 值 |
|---|---|
| API 调用行数 | 120（生成 40 主 + 30 噪声；判分 20 主对 + 30 噪声单条） |
| prompt tokens | 772,763（其中 cache hit 680,192） |
| completion tokens | 14,468 |

## 6 判定

**门 1 未决，原因是仪器而不是样本。**

本探针能确定的事实有三条：

- 策略文本放在系统消息里，在 20 个处境中有 9 个（`0.4500`）把下一轮续写实质改变了：`materially_different` 为 1 的 9 对里，4 对把 bare 排为 X、5 对把 law 排为 X，与 X/Y 位置无关（`analyse.py` 断言）。两臂因此并非没有差别。
- 四道二值项无法说明两种续写里哪一种被策略偏好：D1、D2、D3 在 bare 与 law 两臂都恰好 1.0000，D4 两臂都是 0.9000；160 个主判读项里 156 个是 1。四道项没有留下策略文本可以移动的余量。
- 因此总均值差 `0.0000`（law − bare）不是“策略无效”的测量，而是“这四道项在这个样本上饱和、看不见策略效应”的测量。一个饱和的 rubric 产出的零不携带关于效应的信息。

按[预注册](../method/prereg.md) §1 的规则，差落在噪声内即门 1 失败；但那条规则预设仪器有分辨率，而本批仪器没有，所以把它套在这里得到的“失败”不是可用的判定。**门 1 记为未决**，等待一个有余量的仪器重跑；最便宜的修法是同批处境、同模型、同一条门换成配对强制选择（[探针 3](probe-3.md)），而不是先改题再猜。

### 6.1 原判定（已撤回）

下面的判定是本探针第一次写下的读法，保留在此作为记录的撤回，不是现状。

> **门 1 判为失败。**
>
> 判它的数字：总均值差 `0.0000`（law − bare），噪声池化 SD `0.0456`，`0.0000 ≤ 0.0456`；四个维度分差全为 0.0000；预期方向是 law 更高，观测到的差不是“更大且同向”，而是零。按预注册的规则，差落在噪声内即门 1 失败，本项目不应带着这个信号进入 M2 微调，而要先改题——更准确地说，先改量它的仪器。
>
> 这条判定有一处必须说清的边界：**仪器已经饱和**。D1、D2、D3 在两臂都恰好 1.0000，D4 两臂都是 0.9000，160 个主判读项里 156 个是 1。四道二值项在这个样本上没有留下可供策略文本移动的余量，所以这个零不是“策略无效”的证明，而是“这四道项看不见策略效应”的测量。门 1 失败是规则给出的结论；失败的最便宜修法是先换一个有余量的仪器（例如把“越权动作次数”这类可数项做成主项、给评委法条原文，或换一个跨家族评委），再重跑同一条门，而不是先改题再猜。
>
> 负对照（`analyse.py` 每次运行都做）：把 SIT01 law 侧 `D1_authority` 从 1 翻成 0，总均值差从 0.0000 变成 −0.0125，摆幅 0.0125——**一个判读项的翻向就比整个观测差大**。这正是“差在噪声内”的另一种说法，也说明本批 n 与判读精度不足以支撑任何非零结论。

撤回原因：上面那条规则被套在一个已经饱和的仪器上，它没有机会触发。第 1 条事实（9/20 实质不同）与第 3 条事实（rubric 无余量）同时成立时，“差在噪声内”只能说明这套四项看不见效应，不能说明效应不存在。

## 7 与探针 1 的差别

探针 1 的 `nolaw` 臂不是自然基线：它仍是一个 harness 会话，带着该 harness 自己的 agent 系统提示，证据是 `nolaw` 的回答照样使用 `tool: bash({...})` 这套工具语法，而工具格式只能来自 harness。它因此只能说"策略作为项目指令在场时没测出差别"，不能说"策略没有效应"，门 1 未决。本探针把系统消息整条删掉作为 `bare` 臂：请求里真的只有一条 user 消息（457–637 prompt token，对照 law 臂的 19,939–20,119），两臂的 user 消息逐字节相同，于是"有没有策略原文"成为唯一变量，自然基线第一次被实测。同四道项、同样盲评、同样 6 个信号框架下，这次的零是一个被测出来的零，而不是一个缺席的观测；同时它也暴露了更贵的那件事——探针 1 的 +0.01 与这里的 0.0000 都不是策略的效应量，而是这套四项仪器没有余量的读数。

## 8 限制

- **评委与受试同家族**（都是 `deepseek-flash`），"无差别"不是独立观测。预注册 §3 要求抽 20% 由第二家族复核，本探针未做。
- **每对只判一次**，预注册 §3 要求每条轨迹判 3 次。噪声测量只覆盖温度，不覆盖评委自身的判读方差。
- **S6 零条可用**（见 §2），六信号的覆盖实际是五个信号。
- **一条回答触到 600 token 上限**：SIT03 bare 在主比较与三次噪声采样里都跑满 600 token（4 次 `finish_reason: length`）。这是该臂真实行为的一部分（它没按 120 词约束作答），但它被截断，判分看到的是被截断的版本。
- **峰值计价与节假日**：价格按工作日的峰值窗口判定，未排除中国法定节假日（规格页说明节假日全按非峰值）。
- **预跑调用未逐条记账**：确定模型与参数时对端点做过约 10 次小请求（模型列表、thinking 开关、温度行为探针），每次几十 token，估计合计 < $0.001，未写入 `calls.jsonl`。`calls.jsonl` 只含探针本身的 120 次调用。
- **CSV/JSONL 里不含密钥**：`calls.jsonl` 只记 usage、成本与回答，不记请求头；仓库里 `git grep` 密钥前 8 字符为空。
